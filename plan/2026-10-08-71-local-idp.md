# Plan: Log in locally with test users

## Approved decisions (self-contained)

- **Provider:** `ghcr.io/navikt/mock-oauth2-server:6.0.4` as compose service
  `idp`, with `JSON_CONFIG: '{"interactiveLogin": true}'` and
  `SERVER_PORT: "8080"`. The login page takes a username and a claims JSON.
- **One address:** `idp.localhost:8080`.
  - The host publishes `127.0.0.1:8080:8080`; browsers resolve `*.localhost`
    to loopback.
  - In compose, `idp` has the network alias `idp.localhost`.
  - The issuer is `http://idp.localhost:8080/refs`.
- **`web`:**
  - `depends_on: idp`;
  - OIDC settings: `OIDC_METADATA_URL`, `OIDC_CLIENT_ID=refs-local`,
    `OIDC_CLIENT_SECRET=dev-only-not-a-secret`;
  - role groups: `refs-users`, `refs-reviewers`, `refs-admins`;
  - port bound to `127.0.0.1:8000:8000`.
- No profile, no app change, nothing in the Dockerfile or `infra/`. CI
  (`docker compose build`, `docker compose run --rm app pytest`) is
  unchanged.
- **README test users:**

  | Username | Claims |
  | --- | --- |
  | `admin` | `{"name": "Test Admin", "groups": ["refs-admins"]}` |
  | `reviewer` | `{"groups": ["refs-reviewers"]}` |
  | `sales` | `{"groups": ["refs-users", "sales"]}` (a source needs access group `sales` first) |
  | `nobody` | `{}` |

  Fallback: add `127.0.0.1 idp.localhost` to `/etc/hosts`. Port 8080 is
  named, and changing it means editing three places.
- `scripts/check_local_login.sh` repeats the curl login flow for the four
  users and checks `/me`.
- **Coder handoff:** 3 file-editing steps, 3 files. Steps 1–3 go to the
  `coder` agent. Step 4 goes beyond the approved spec; the user approved it
  with this plan, so it goes to the `coder` agent as well.

## Steps

1. **Compose.** `docker-compose.yml`:
   - Add the `idp` service after `db` (line 10): `image`, `ports:
     ["127.0.0.1:8080:8080"]`, `environment` (`SERVER_PORT`,
     `JSON_CONFIG`), and `networks: {default: {aliases: [idp.localhost]}}`.
     Add a comment saying it is dev only and mints any login.
   - `web` (lines 27–40):
     - port `"127.0.0.1:8000:8000"`;
     - the OIDC and role variables above;
     - `depends_on` adds `idp:` (no healthcheck: the image has no shell
       tools, and authlib reads the metadata on the first `/login`, not at
       start).

   → verify by `docker compose config -q` and `docker compose up -d web`,
   then `curl -s
   http://idp.localhost:8080/refs/.well-known/openid-configuration` shows
   the issuer `http://idp.localhost:8080/refs`. From inside web, the same
   URL gives the same issuer: `docker compose exec -T web python -c
   "import httpx; print(httpx.get('<url>').json()['issuer'])"`.

   Traps:
   - keep `app` and `worker` free of `depends_on: idp`, so that `docker
     compose run --rm app pytest` doesn't start it;
   - the alias must be under `networks.default`, or Docker DNS won't
     answer it.
2. **Check script.** `scripts/check_local_login.sh` (`#!/usr/bin/env bash`,
   `set -euo pipefail`, executable):
   - for each of the four users:
     - a fresh cookie jar;
     - `curl` `/login` and take the redirect;
     - POST `username` and `claims` (`--data-urlencode`) to it and take the
       redirect;
     - `curl` that callback with the jar, then `curl /me`;
   - compare the roles with the expected list: admin → admin, reviewer,
     user; reviewer → reviewer, user; sales → user; nobody → none. For
     `nobody`, `/admin/sources` must also return 403;
   - print one line per user; exit non-zero on any mismatch;
   - `BASE` (default `http://localhost:8000`) can be overridden.

   → verify by running it against step 1's stack: 4 OK lines, exit 0. Then
   change one expected role temporarily: a non-zero exit.
   Traps: the jar lives in `mktemp -d`, removed on exit; no Python
   dependency; `jq` may not be installed, so compare with `grep`/`sed` on
   the small `/me` JSON.
3. **README.** A new `## Local login (test users)` section after
   `## Dependency lock`:
   - `docker compose up web worker`, then open http://localhost:8000;
   - the users table above, with what each one gets;
   - the `sales` note: as admin, give a source the access group `sales`
     first;
   - the `/etc/hosts` fallback, and the port 8080 note;
   - `scripts/check_local_login.sh` to check it;
   - a warning that this provider logs anyone in as anything: local only.

   → verify by reading it and following it from a stopped stack.
4. **The worker and web get the model settings** (beyond the spec;
   approved with this plan).
   Today compose passes no model settings to `worker` or `web`, and on Linux
   `host.docker.internal` isn't defined. So extraction (`EXTRACT_MODEL`),
   drafting (`DRAFT_MODEL`) and research (`BRAVE_API_KEY`) can't run
   locally, even though the README tells you to `export` them. For testing
   the logic, `worker` and `web` get:
   - `EXTRACT_MODEL: ${EXTRACT_MODEL:-}`, and the same for
     `EXTRACT_MODEL_OPTIONS`, `DRAFT_MODEL`, `DRAFT_MODEL_OPTIONS` and
     `BRAVE_API_KEY`, passed through from the shell (empty when not set);
   - `extra_hosts: ["host.docker.internal:host-gateway"]`.

   → verify by `docker compose config` showing the variables set from the
   shell, then one upload extracted with the local Ollama model (the README
   Docker options with `"destination": "local"`), on a public or made-up
   document, not a confidential one.
   Traps: confidential documents only go to `local` models; don't commit
   any key; `${VAR:-}` keeps compose quiet when the variable isn't set.

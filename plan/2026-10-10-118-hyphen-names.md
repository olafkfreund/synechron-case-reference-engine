# Plan: A hyphenated client name is not matched when written with a space or run together

`_pattern` splits a registered name on whitespace only, so for protected
"Zorp-Tek" the forms "Zorp Tek", "ZorpTek" and "Zorp–Tek" leak. These
decisions are copied from the spec:

- Split the name on whitespace and on every dash `_JOIN` already accepts. Join
  the words with `_JOIN`, as today.
- A name that is only dashes stays a literal, so the pattern is never empty.
- Make one change in `_pattern`. `apply`, `blocked`, `has_name` and `scrub`
  all pick it up.
- The change only adds matches, so a name with no dash builds the same
  pattern as today.

## Steps

1. `app/anonymise.py:12` and `:33-34`:
   ```python
   _SEP = r"[\s\-‐‑–—]"
   _JOIN = _SEP + "*"
   ...
   def _pattern(name: str) -> re.Pattern:
       words = [w for w in re.split(_SEP + "+", name) if w] or [name]  # "-" alone stays literal, never empty
       body = _JOIN.join(re.escape(w) for w in words)
   ```
   The flags line and the return line stay as they are.

   Verify with `pytest -q tests/test_anonymise.py`: the existing tests pass.

   Traps:

   - #119 edits the flags line just below. If #119 merges first, keep its

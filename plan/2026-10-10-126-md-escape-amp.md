# Plan: Markdown output does not escape &, so an HTML entity can spell a protected name

These decisions are copied from the spec:

- Add `&` to the escape class in `render.md()` (`app/render.py:276`) and to its
  docstring. `\&` is a CommonMark backslash escape, so it renders as `&` and no
  entity is decoded.
- Every value in the Markdown template already goes through `| md`. Only the
  static text the code writes itself does not.

Size: 2 steps, 2 files. Below the coder handoff threshold.

## Steps

1. `app/render.py:272-276`:
   - change the class to `r"([\\`*_\[\]<>#|~&])"`;
   - add `&` to the docstring's list: "backslash, backtick, * _ [ ] < > # | ~ &
     are escaped".

   Verify with `pytest -q tests/test_render.py tests/test_industry.py`.

   Traps:
   - URLs in the Markdown industry section go through `md`, so `?a=1&b=2`
     becomes `?a=1\&b=2`. CommonMark renders that as `&`. If an existing test
     asserts a raw `&` in Markdown, update it to `\&` and name it in the
     commit and in this plan.
   - Docx, pptx and pdf don't use `md`. Don't touch them.

2. `tests/test_render.py`: after `test_markdown_values_cannot_create_structure`
   (`:144`), add `test_markdown_escapes_ampersand`, which checks that:
   - `"\\&#114;" in render.md("Zo&#114;p")`;
   - `"&#" not in render.md("Zo&#114;p").replace("\\&#", "")`;
   - `render.md("R&D") == "R\\&D"`.

   Verify that it fails on main.

## Tests

The full suite must pass, and the new test must fail on main.

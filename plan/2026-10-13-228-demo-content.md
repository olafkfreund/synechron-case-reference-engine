# Plan: The demo shows complete case studies

Branch `feat/228-demo-content`, worktree `../refs-engine-228`. It is based on
main, which has all of #212 (points, prose, `tech_references`, diagrams and
the case-study output) and #222 (completeness).

## Approved decisions

- **Data only, plus the seed script.** No app code changes. `demo/cases.json`
  keeps its shape (`sources`, `clients`, `cases`). Each case keeps `source`,
  `file`, `paragraphs`, `status` and `case`.
- **Documents.** Each `paragraphs` list becomes 600 to 1,200 words of plainly
  fictional text, in this order:
  1. title
  2. situation and drivers
  3. scope and deliverables
  4. approach and phases (with team and duration)
  5. configuration and integrations
  6. technical references
  7. outcomes with named metrics
  8. lessons learned (delivered work only)
- **Each `case` carries:**
  - `points`: 3 to 6 per section for challenge, solution, implementation and
    configuration, each `{value, source_quote}`
  - `prose` for those four sections: `{text, by_reviewer: true, flags: []}`,
    80 to 200 words, built only from that section's points
  - `tech_references`
  - `outcomes` with real metric names, never "metric"
  - `period`, `duration_months` and `team_size`

  The seed stamps `extraction_version`; it isn't written by hand.
- **Names.** Only the 10 fictional clients (Contoso, Northwind, Fabrikam,
  Woodgrove, Tailspin, Litware, Adventure Works, Wide World Importers,
  Proseware, Alpine Ski House) and generic vendor and product names. No real
  banks, people, deal values, or places finer than a country or region.
- **The completeness mix** (`app/completeness.py`):

  | Group | Cases | Target |
  |---|---|---|
  | Complete | cases 0 to 3 and 5 to 8 | 9/9, each with a seeded diagram |
  | Deliberately partial | Litware citizen portal (case 4), approved | 6/9: no diagram, no configuration, 2 technologies, with a seeded override row |
  | Waiting for review, clean | Northwind loyalty (10), Litware records (11) | 8/9, no diagram, plus one seeded `document_images` candidate each |
  | Waiting for review, flagged | Contoso fraud scoring (9) | Solution prose is `by_reviewer: false`, with one flag |
  | Engagements | Fabrikam SOW and change order (12, 13) | contracted scope, no outcomes or lessons, the merge flow kept |
- **Diagrams** are drawn at seed time with Pillow: 3 or 4 labelled boxes with
  arrows, using that case's own technologies. They are stored as `diagrams`
  rows with `created_by='demo-seed'` and added to `case.diagrams` as `ready`
  with a caption. No image files go into the repository.
- **Refresh rule.** The seed inserts or updates, keyed on `(source_id,
  external_id)` of the demo sources only.
  - A changed checksum updates the document (text, checksum and
    `updated_at`) and the case in place. Status goes back to the file's.
    Approved cases are re-stamped `approved_by='demo-seed'`. The case's
    seeded `diagrams` and `document_images` rows are replaced.
  - An unchanged document does nothing.
  - Nothing is ever deleted.
- **Hard checks at seed time, before any write.** If any check fails, the
  script exits non-zero, names the file and the field, and writes nothing:
  - every `source_quote` is in its `to_markdown` text (`quote_in`)
  - `check()` leaves nothing `unsourced`, except the existing planted
    `region` example
  - `by_reviewer` prose gives no `check_prose` flags
- **Only fictional names (decision, 2026-10-13).** A test checks that
  `client_mention`, `organisations`, and capitalised multi-word organisation
  names in the paragraphs come from the demo `clients` list (names and
  aliases) or a short fixed allow-list of vendors and products. There is no
  deny-list.

## Steps

1. **`scripts/seed_demo.py`: validate first, then insert or update.**
   - Split `main()` into two parts:
     - `validate(demo) -> list[str]` checks the data only: quotes, `check()`
       results, and prose flags, using `to_markdown` on the built bytes.
     - The writer runs only if `validate()` returns nothing; otherwise print
       the errors and return 2.
   - Stamp `case.extraction_version = EXTRACTION_VERSION` before writing.
   - **Refresh path.** When a row exists and the checksum differs, run
     `update documents set text, checksum, updated_at=now()` and
     `update cases set data, summary, search_text, basis, status` for that
     document id only. Approved cases are stamped as now. Delete and re-insert
     that case's demo-seed `diagrams` and its document's `document_images`.
   - **Diagram helper.** `draw(labels) -> png bytes` uses
     `PIL.Image/ImageDraw` with the default font and about 800x320 px. Insert
     it into `diagrams(case_id, png, created_by)` and append
     `Diagram(id, caption, status="ready", width, height)` to the case data.
   - **Override row.** For the partial approved case, insert one
     `case_approval_overrides` row only if none exists for that case, with
     the reason "Demo: approved below the minimum to show the override".
   - **Verify:** `docker compose build app && docker compose run --rm app pytest tests/test_seed_demo.py`
     still passes with the old data (`test_seed_twice`).
   - **Traps:**
     - Every write must carry a demo `source_id`. Never write to rows
       without one.
     - `ReferenceCase` uses `extra="forbid"`, so data keys must match the
       schema exactly.
     - The demo's `to_markdown` path in tests is monkeypatched to join
       paragraphs, so quotes must survive both that and real Docling.
       Prefer quotes that sit inside one paragraph.

2. **`tests/test_seed_demo.py`: the guard tests, written before the content.**
   - Each test reads `demo/cases.json`.
   - `test_every_quote_is_in_its_document`: data-only, through
     `seed.validate`.
   - `test_only_fictional_names`: check `client_mention` and `organisations`,
     plus a regex for capitalised runs of two or more words in the
     paragraphs. Each must come from the clients' names and aliases, or from
     the `ALLOWED` set in the test (a few dozen vendors and products, such as
     ServiceNow, Kafka, Azure, Kubernetes, PostgreSQL, and the SWIFT and ISO
     standards).
   - `test_refresh_updates_only_demo_rows`: seed, change one case's
     paragraphs in a copy of the data (monkeypatch `seed.DATA`), and seed
     again. That document and case are updated. Another demo case is
     untouched. A non-demo source with the same `external_id` is untouched.
   - `test_completeness_mix`: after seeding, check each case's
     `score(checklist(...))` against the table above, and that Contoso fraud
     has exactly one flag.
   - Mark the content-dependent tests (`test_only_fictional_names` and
     `test_completeness_mix`) `xfail(strict=False)` until step 6, then remove
     the marks.
   - **Verify:** the suite runs, and the guard tests pass or xfail as
     intended.
   - **Traps:** keep `clean()` deleting only demo sources and clients.

3. **`demo/cases.json`: content batch 1, cases 0 to 3** (Contoso claims
   intake, Northwind stock forecasting, Woodgrove payments gateway, Tailspin
   route planning). All four are complete, 9/9.
   - Write paragraphs, points, prose, references, outcomes, period, duration
     and team size for each.
   - **Verify:** `pytest tests/test_seed_demo.py -k "quote or fictional"`.
   - **Traps:**
     - Prose must reach 80 words or more for challenge and solution.
     - Every number and name in the prose must be in that case's quotes.
     - Outcome metrics must not be "metric".

4. **`demo/cases.json`: content batch 2, cases 4 to 7** (Litware citizen
   portal, which is the deliberately partial 6/9 case; Adventure Works
   booking; Wide World Importers order automation; Proseware billing).
   - **Verify:** as in step 3.
   - **Traps:** Litware citizen portal has exactly 2 technologies, no

5. **`demo/cases.json`: content batch 3, cases 8 to 11** (Alpine Ski House

   - **Traps:**

     - Northwind loyalty and Litware records get `document_image: true`, so

6. **`demo/cases.json`: content batch 4, cases 12 and 13** (the Fabrikam SOW

   - **Verify:** `docker compose build app && docker compose run --rm app pytest`,

## Deviations

- Step 1:
  - The data file gains entry keys `diagram`, `document_image` and
    `override`, alongside `expect_flag`, so the seed knows what to add.
  - A changed document also gets a new `s3_key`, so downloads serve the new
    bytes.
  - Pillow (already used by `app/diagrams.py`) is in `requirements.lock` but
    not declared in `pyproject.toml`. That's tracked separately and not
    changed here.
- Review fixes:
  - `check_prose` runs on every prose item, reviewer prose included. Four
    texts were reworded: case 9 configuration, case 10 configuration, case
    11 challenge, case 12 solution.
  - Contoso fraud keeps exactly one flag ("FraudSense").
  - The planted exemption is limited to `region`.
  - The `draw()` guard needs at least 2 technologies.
  - Tests cover each failing-validation path, and the override count is
    scoped to the demo case ids.
  - Accepted: Contoso fraud has a diagram; vendor names are in ALLOWED.

## Rollback

Revert the branch. The next `demo.sh up` with the old data and the old seed
skips existing rows, so the refreshed demo content stays until
`scripts/demo.sh reset` is run. No non-demo data is involved.

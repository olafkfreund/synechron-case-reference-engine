# Plan: MCP server, phase 2 (outputs, research, library, briefs)

Worktree `../refs-engine-249p2`, branch `feat/249-mcp-phase2`, based on main
with phase 1 merged. One PR.

## Approved decisions (from the spec)

1. **Lifts.** These route bodies become service functions. The portal routes
   become thin wrappers, with the same behaviour and bytes.
   - `render.produce(conn, user, fmt, case_ids, research_id, ack, library_ids)
     -> (bytes, mime, filename)`, from `render.generate` (`app/render.py:811-833`).
     It runs `build`, images, `make` and the `generations` insert.
   - `research.start(conn, user, query, case_id=None) -> rid`, from
     `research_send` (`app/research.py:156-168`). It runs `finalize`, the
     `visible_case` check, the insert and the job.
   - `library.save_item(conn, user, research_id, brief_id, n, topic) -> lid`,
     from `library.save` (`app/library.py:69-115`). The portal keeps its
     `_refuse` page handling around it.
   - `brief.create(conn, user, rid, n, title) -> bid`, from `brief.start`
     (`app/brief.py:134-148`).
   - `brief.output(conn, user, bid, fmt)` and `library.output(conn, user,
     lid, fmt)`, from their `download` routes. Each returns
     `(bytes, mime, filename)`.
2. **Signed download links.**
   - **Token.** `itsdangerous.URLSafeTimedSerializer(app secret,
     salt="mcp-download")` over `{k: user_key, kind: "case"|"brief"|"library",
     f: fmt, …ids}`, valid for 10 minutes. Nothing is stored.
   - **Route.** `GET /mcp/download/{token}` lives in the **main** app. It
     authenticates with the portal session (`current_user`) or a bearer
     token (phase 1's `EntraVerifier` plus `user_from_token`), and the
     token's `k` must equal the caller's key, otherwise 403.
   - **Download.** It re-runs `produce`/`output` with the caller's current
     rights (404 when hidden) and writes `generations` then.
   - **Errors.** An expired or tampered token gives 410 "this download link
     has expired; ask for a new one".
   - **Headers:** attachment, `no-store`, `nosniff`.
   - **Privacy.** The token never goes into logs or `tool_calls`, and
     `tool_calls` records outcome `ok` for the download.
3. **Tools** (phase 1 wrapper `_run`: user from the token, plain-user view,
   audit, rate limit, preface, portal errors):

   | Tool | Behaviour |
   |---|---|
   | `generate_output(case_ids≤3, format, research_id?, library_ids≤3, ack?)` | Validates through `render.build` (no bytes, no audit row) and returns `{download_url, expires_in: 600, format, markdown}`. |
   | `start_research(question≤1000, case_id?)` | `build_query(question, clients)` (the LLM scrub), then `research.start`. Returns `{research_id, query, status}`. |
   | `get_research(research_id)` | Owner only (404 otherwise). Returns `{status, query, claims: visible_claims(...)}`, where each claim has type, statement, quote, publisher, URL (public web) and date. |
   | `save_library_item`, `list_library(q?, topic?, kind?)`, `get_library_item(library_id)` | Same rows and `apply`/`blocked` as the portal. |
   | `create_brief(research_id, n[], title?)`, `get_brief(brief_id)` | `brief.create`; owner only; `brief_section` (`Withheld` gives `isError` with the portal text). |
   | `download_brief(brief_id, format)`, `download_library_item(library_id, format)` | Signed links. |

   - **Hints.** `start_research` and `create_brief` are not idempotent and
     are open-world. The `get_`/`list_` tools are read-only. The `download_`
     and `generate_output` tools are read-only, since the link writes the
     audit.
4. **Caps.** On top of the 60/min limit, `start_research` and
   `create_brief` allow 10 calls a day per user, counted in `tool_calls`
   with outcome `ok` over a rolling 24 h. Over the cap gives `isError`
   "daily limit reached for <tool>".
5. **Data.** Public web URLs in research claims may be returned. Internal
   document URLs never are (they stay behind `/go`). The untrusted-content
   preface goes on every text payload, and technical notes are capped at
   the portal limit.

## Steps

1. **Lift `render.produce`, and make `generate` a wrapper.**
   - → verify: a byte-equality test, `/generate` before and after for every
     format in `OUTPUTS` on the same seeded case. Pin the bytes by hashing
     the output of the pre-lift code in the test fixture setup: run the old
     code path once in the test, or compare `produce()` with
     `generate`'s response.
   - Then `pytest tests/test_render.py tests/test_industry.py`.
   - Traps:
     - keep the `PdfError` 503
     - keep the `friendly()` 400/404 page for browsers in `generate`
     - the audit row still goes in after `make` succeeds
2. **Lift `research.start`, `library.save_item`, `brief.create`,
   `brief.output` and `library.output`.** The portal routes become
   wrappers.
   - → verify: `pytest tests/test_research*.py tests/test_library.py
     tests/test_brief*.py`, all unchanged and green.
   - Trap: `library.save`'s HTML error page (`_refuse`) stays in the route,
     and the function raises `HTTPException`.
3. **Signed download route (decision 2)**, in `app/mcp_server.py`, wired
   from `create_app` when MCP is enabled.
   - → verify (`tests/test_mcp_download.py`):
     - the session path and the bearer path, same user, give 200
     - another user gives 403
     - expired and tampered tokens give 410
     - a case hidden after the link was made gives 404
     - the `generations` row is written on download
     - `no-store` is set
     - the token is absent from logs (caplog) and from `tool_calls`
     - brief and library kinds work
4. **Tools (decision 3).** Register them in `register()` with `outputSchema`
   models, and cap `start_research`/`create_brief` (decision 4).
   - → verify (`tests/test_mcp_tools.py`):
     - schemas validate
     - `start_research` returns the same scrubbed query as the portal
       preview for the same question and queues exactly one job
     - `get_research` on another user's research gives `not_found`
     - a claim naming a protected client is dropped
     - `save_library_item` and `create_brief` give the same rows as the
       portal routes
     - `get_brief` on a withheld brief gives the portal's message
     - the daily caps apply
     - leak tests (internal URL, `documents.text`, protected name, bid
       text, token)
5. **Docs.** `docs/mcp.md` gets the new tools, the download flow (open the
   link while signed in to the portal, or `curl -H "Authorization: Bearer
   …" -o out.docx <url>`) and the daily caps.
6. **Smoke test, by the coder, against its own stack.** With
   `MCP_ENABLED=1` and the dev token:
   1. `generate_output`, then fetch the link with the bearer token: 200 and
      a docx magic number
   2. `start_research`: a job is queued (no Brave key needed to queue it)
   3. `get_research` on the queued run: status `queued`

   Report HTTP statuses only.
7. **Full suite**, then (by the session) the Opus and Codex reviews and the
   PR:
   `docker compose build app && docker compose run --rm app pytest`.

## Rollback

Revert the merge commit. The lifts are behaviour-preserving, so reverting
returns to the inline route bodies. MCP is still behind `MCP_ENABLED`.

## Deviations

- Step 1:
  - The byte test compares `produce()` with `/generate` after the lift, so
    it pins the wrapper, not the pre-lift bytes. The existing render tests
    (content, anonymisation, audit, PDF 503) are what guard the lift
    itself.
  - PDF formats are left out of the byte test (converter output is not
    byte-stable), but are covered by the existing PDF route tests.
- Step 2: no test edits. A refused `library.save` now rolls back instead of
  committing; nothing is written before a refusal, so the effect is the
  same.

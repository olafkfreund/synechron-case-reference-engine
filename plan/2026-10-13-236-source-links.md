# Plan: Case cards link to their source documents and folders, safely

Branch `feat/236-source-links`, worktree `../refs-engine-236`. One PR.

## Approved decisions (from the spec)

- `documents.web_url` and `documents.folder_url` are nullable. Null means no
  link: uploads, S3 and DataSync shares, or not crawled since this change.
- Links come only from the source API's own fields:
  - SharePoint: the item's `webUrl`, and the parent's `webUrl` looked up once
    per parent per crawl.
  - Confluence: `c.base + _links.webui`, never `_links.base`. An attachment
    links to its page. A page's folder is its last ancestor page.
- `safe_link(url, host)` keeps a URL only when:
  - its scheme is `https`
  - its host exactly equals the allowed host (the drive's `webUrl` host, or
    the configured `base_url` host)
  - it has no user or password part
  - it's at most 2,000 characters

  Otherwise it stores null. The document is kept.
- The backfill rides on the existing re-check loops:
  - SharePoint: one `$select=webUrl,parentReference` call per live document
    with null links, once.
  - Confluence: no extra calls.
  - `skip_unchanged` and the same-bytes path write the links too, with no
    new version.
- The card gets one `source_docs(case_ids, user)` query per page, with the
  `VISIBLE` conditions (live, in the user's groups). Merged cases list every
  member.
- Titles:
  - Reviewers and admins: always `clean(title)`.
  - Plain users: `clean(title)` only for a linked and referenceable client;
    otherwise "N document(s) in <source>".
  - The links stay. Nothing else shows "[withheld]".
- The template:
  - a collapsed "Source documents (N)" disclosure
  - "Open" and "Open folder" links with `target="_blank"
    rel="noopener noreferrer"`, autoescaped
  - the URL never shown as text
  - no link: "stored in the engine; ask a reviewer"
- Render and output code never reads these columns.

## Steps

1. **`sql/schema.sql`: the columns.** After the `documents.updated_at` lines,
   add
   `alter table documents add column if not exists web_url text;` and the
   same for `folder_url`.
   → verify: `docker compose build app && docker compose run --rm app pytest tests/test_db.py`
   Traps: keep them nullable. The schema runs on every start, so the
   statements must be idempotent.

2. **`app/ingest.py`: carry the links.**
   - `ingest()` (`:77`) and `skip_unchanged()` (`:168`) take
     `links: tuple[str | None, str | None] = (None, None)`.
   - Write `web_url` and `folder_url` in the new-version upsert, in the
     same-bytes branch's update, and in `skip_unchanged`'s update.
   - Write them only when `links != (None, None)`, so an S3 crawl or upload
     never nulls links set earlier. Use `coalesce(%s, web_url)`.
   - Add tests in `tests/test_ingest.py`:
     - the links are stored on a new document
     - the same bytes with links fill them in without bumping `updated_at`
     - `(None, None)` keeps the existing links
   → verify: `pytest tests/test_ingest.py`
   Traps: `updated_at` must not move on the same-bytes path (#215). Leave the
   `skip_unchanged` checksum logic alone.

3. **`app/crawl.py`: `safe_link()` and SharePoint.**
   - Add the `safe_link(url, host)` helper near the top, using
     `urllib.parse`.
   - Read the host once per crawl:
     `g.get(f"{GRAPH}/drives/{drive}?$select=webUrl")`. If it fails, set
     host = None, which turns all links into null; the crawl goes on.
   - In `handle()` (`:213`), build the links from `item.get("webUrl")` and
     the parent's `webUrl`. Look up `parentReference.id` through a per-crawl
     dict cache: `items/{pid}?$select=webUrl`, with errors giving None. Pass
     the links into `ingest(...)` and `skip_unchanged(...)`.
   - In the live re-check loop (`:301`), for live documents whose `web_url
     is null`, run one `items/{iid}?$select=webUrl,parentReference` call and
     an `update documents set web_url, folder_url`. A failure there is
     ignored and never withdraws the document.
   - Add `tests/test_crawl_sharepoint.py` fixtures and tests:
     - The fake Graph (`Site`) returns `webUrl` on items and
       `parentReference: {"id": …}`, and answers
       `drives/{drive}?$select=webUrl` and `items/{pid}`.
     - Tests:
       - the links are stored
       - an `http` or cross-host `webUrl` is stored as null
       - the parent is fetched once for two files under it
       - a live document with null links is backfilled with no new version
       - a backfill failure doesn't withdraw the document
   → verify: `pytest tests/test_crawl_sharepoint.py`
   Traps:
   - The extra calls go through the same `Graph` client (with retry and
     throttle); don't add a new client.
   - The `$select` query string in the fake's URL matching: the fake strips
     `?` unless `token=` is present, so match on the path.
   - Don't count the backfill call as a permission check (`checked`).

4. **`app/crawl.py`: Confluence.**
   - The host is `urlparse(config["base_url"]).hostname`.
   - In `do_page()` (`:428`), the page links are `c.base + page["_links"]["webui"]`
     and the last ancestor's webui. When the ancestor has no `_links.webui`,
     the folder is None. Run both through `safe_link`.
   - Attachments get the page's `web_url` as both values.
   - Pass the links to `ingest` and `skip_unchanged`.
   - In the re-check loop (`:540`), write the links when they're missing,
     from the page already fetched.
   - Extend the fake `Conf` so pages carry `_links: {"webui": "/spaces/ENG/pages/<id>", "base": <forged>}`.
   - Tests:
     - a page and an attachment get `c.base`-built links
     - a forged `_links.base` is ignored
     - a re-check backfills the links
   → verify: `pytest tests/test_crawl_confluence.py`
   Traps:
   - `c.base` already includes `/wiki`, so check it isn't doubled with
     webui.
   - Data Center vs Cloud ancestors: on Cloud the v2 ancestors list has
     ids only, so the folder may be None there. That's accepted.

5. **`app/search.py`: `source_docs()` and `view()`.**
   - Add `source_docs(conn, case_ids, user) -> dict[cid, list]`: one query
     over cases `c` joined to member cases `m` (`m.id = c.id or
     m.merged_into = c.id`), then documents and sources, filtered by
     `d.deleted_at is null and d.acl_groups && %s::text[]`.
   - Build each entry with the section 4 rules, using `clean()` and the
     client's `referenceable` and linked flags, which `search()` already
     loads.
   - Have `view()` take `sources=`. `browse()` and `results()` call
     `source_docs` once per page.
   → verify: `pytest tests/test_search.py`
   Traps:
   - Pass the role check (`"reviewer" in user.roles`) in; don't re-derive
     it.
   - It must not add a query per row.

6. **`app/templates/search.html`: the disclosure.**
   - On each card (browse rows, `top` and `others`):
     `<details><summary>Source documents ({{ n }})</summary>`, with one
     line per document: the title or the count text, then the links as in
     the decisions.
   - No `| safe`.
   - Tests in `tests/test_search.py`:
     - a referenceable client shows its titles and links
     - a protected client shows the count text, the links, and no title
     - a reviewer sees the titles
     - a merged case lists its members
     - a withdrawn or invisible document never appears
     - an upload shows "stored in the engine; ask a reviewer"
     - a `"` or `<` in a URL is escaped, and `rel="noopener noreferrer"` is
       present
   → verify: `pytest tests/test_search.py tests/test_ui.py`
   Traps: the user-guide test checks bold labels in templates. If
   `docs/user-guide/bid-team.md` mentions the cards, add one line about
   "Source documents".

7. **The full suite, then the PR.**
   → verify: `docker compose build app && docker compose run --rm app pytest`,
   run alone (never two compose runs at once in this worktree). The session
   reviews it, opens the PR, and later checks it by hand in the demo after
   a re-crawl.

## Deviations

- Step 3: a SharePoint document whose `webUrl` fails `safe_link` stays
  null, so it gets one metadata call on every crawl, not just once. This is
  accepted: it's one call per such document per crawl, and a marker column
  isn't worth it.
- Steps 5-6:
  - `source_docs(case_ids, user, clients)` opens its own connection, like
    the module's other helpers.
  - Documents whose titles are hidden are grouped per source as
    "N documents in <source>", with their links kept.
  - The reviewer title rule is tested at function level.
  - The user guide bolds only "Open" and "Open folder".
- Review fixes:
  - Links are never rendered. Cards link to `/go/{id}` and
    `/go/{id}/folder`, which re-check visibility and 303 to the stored
    link with no-store and no-referrer. A SharePoint path naming a
    protected client never appears in the portal.
  - The backfill is skipped when there's no drive host, or for items
    handled in this crawl.
  - New tests cover the Confluence skip-path links and one permissions
    call per item.

# Plan: The local model's JSON replies are data, not the schema

Worktree `../refs-engine-245`, branch `fix/245-schema-echo`. One PR.

## Approved decisions (from the spec)

1. **`_schema_echo(text, schema) -> bool`** returns true when the reply is a
   JSON object that either:
   - has at least 2 of `$defs`, `properties`, `required`,
     `additionalProperties`, `type`, `title`, and none of the model's
     required field names; or
   - has a single top-level key holding such an object.

   It runs only after validation has failed.
2. **One corrective retry, only on an echo.** The retry sends the same
   system and user messages, plus the reply as an `assistant` turn and the
   user turn: "That was the schema, not the answer. Reply with one JSON
   object containing the data, using the field names above. Do not include
   the schema."
   - It uses the same `extra` options, the truncation check and the overflow
     guard. There is no retry if the longer prompt would exceed `num_ctx`.
   - A second failure raises the existing `ValueError`, with "(after a
     schema-echo retry)" appended.
   - Other validation failures are not retried.
3. **New cue in JSON mode:**

   ```text
   Reply with one JSON object that follows this JSON Schema. The schema describes the format; do not repeat it.
   Schema: {…}
   Example of the shape (values are placeholders): {…}
   ```

   `_example(schema)` builds the example deterministically:
   - strings `"…"`
   - numbers `0`
   - booleans `false`
   - arrays with one item
   - enums take the first value
   - `$ref` resolved
   - nullable takes the non-null branch
4. **Logging.** `log.warning("schema echo: alias=%s model=%s schema=%s")`
   with no content, and a counter `ECHO_RETRIES` for tests.
5. **Eval** (`scripts/eval_json.py`): runs `--calls claims,brief`, `--n 20`
   and `--mode json|schema` on a stored research row and a stored brief
   input, and prints counts only. A per-call `mode="schema"` override is
   adopted only if, over 20 runs, it has 0 echoes, at least as many successes
   as the new JSON mode, and no fewer claims per reply. Otherwise there is no
   override.
6. **Gate for the new cue.** `eval_extraction.py` on the 11 trial documents
   shows no drop in sourced items per document beyond run-to-run noise.

## Deviations

- Step 1:
  - `_schema_echo` checks the schema's *required* names, because
    `ReferenceCase.title` collides with the schema's own `title`.
  - The keyword test exempts `title` and `type`. An echo still needs 2
    keywords and no required names.
  - When a retry would overflow `num_ctx`, the original validation error is
    raised, without the retry suffix.
- `research.page_chars()` counts the real cue, `len(json_cue(...))`, in
  place of `+ 60`.
- Negative controls passed. With the retry off, 3 tests fail. With echo
  detection off, 4 fail. Without the correction turn, 1 fails.
- `eval_json.py` reports `echo` (still failing after the retry) and
  `retries` (first-attempt echoes). Decision 5's "0 echoes" means
  `echo + retries == 0`.
- The main baseline is measured with the demo worker (main code), calling
  `extract_claims` and the brief call directly N times, because
  `eval_json.py` needs this branch's `llm`.
- Eval, first pass:
  - Research claims went from 7/20 (main) to 20/20 (JSON mode, new cue),
    with no retries. Strict schema mode got 17/20, at twice the time.
  - Briefs were 20/20 on all three, but strict schema mode returned empty
    themes, so it gets no override.
  - On the trial documents, one executed contract triaged as not executed.
    At temperature 0 the cue is the cause: the example's placeholder
    `false`/`0`/first-enum values read as answers.
- Fix: the example uses type labels for every leaf (`"<string>"`,
  `"<number>"`, `"<true or false>"`, `"<one of: a | b>"`), with the wording
  "each value shows its type, not an answer". The evals are re-run below.
- Main is deterministic: in 3 of 3 runs doc2 triages as executed. With both
  cue versions, the branch flips it, so the new cue changes triage and
  extraction.
- Decision (by eval): the new cue is opt-in. `shape_hint=True` is used
  only by `research.extract_claims` and `brief.run`. Every other call keeps
  the old cue byte for byte. The schema-echo retry stays on for every call.

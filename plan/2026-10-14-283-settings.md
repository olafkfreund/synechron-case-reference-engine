# Plan: a Settings page for crawl configuration, connection and SSO status

## Approved decisions, carried from the spec

- **No new settings store.** Values come from `os.environ` or the
  `sources` row. The only new table is the audit table
  `source_config_changes`.
- **SSO, session, database and connector secrets are read-only status.**
  A secret shows only "Configured" or "Not configured", from
  `bool(os.environ.get(name))`. The value never reaches a template.
- **`*_MODEL_OPTIONS` is never read.** URLs are shown as scheme, host and
  path only.
- **Test-connection buttons, per-source schedules and model selection are
  out of scope.**
- **Typed config fields per kind.** No other key can be produced.

  | Kind | Root, fixed after creation | Scope, editable | Other |
  |---|---|---|---|
  | `s3` | `bucket` | `prefix`, `include_ext` | `executed_contracts` |
  | `upload` | `bucket`, `prefix` | `include_ext` | `staff` (set at create, never edited), `executed_contracts` |
  | `sharepoint` | `tenant_id`, `drive_id` | `include_ext` | `executed_contracts` |
  | `confluence` | `base_url` | `spaces`, `api_prefix` | `executed_contracts` |

- **Field rules:**
  - `bucket`: `[a-z0-9][a-z0-9.-]{1,61}[a-z0-9]`
  - `prefix`: no leading `/`, no `..` segment, at most 1024 characters
  - `include_ext`: comma-separated, lower-cased, `.` stripped, each
    `[a-z0-9]{1,10}`; empty leaves the key out (crawler default)
  - `tenant_id`: a UUID
  - `drive_id`: `[A-Za-z0-9!_-]{1,200}`
  - `base_url`: `https`, has a host, no user info, query or fragment, port
    absent or 443; trailing `/` stripped
  - `spaces`: one or more, each `~?[A-Za-z0-9_-]+`
  - `api_prefix`: `""` or `/wiki`
- **Edit:**
  - root fields are never read from the form
  - scope fields that are absent from the form leave the stored value
    unchanged, so an ACL-only post still works
  - stored keys the form doesn't know are kept
- **Crawl lock:** the edit transaction starts with
  `pg_try_advisory_xact_lock(2, sid)`. If it's taken, nothing changes:
  - a browser gets `303 /admin/sources?notice=crawling`
  - any other caller gets 409, the `refuse()` pattern at
    `app/main.py:310`
- **A scope change** (prefix, include_ext, spaces or api_prefix) sets
  `cursor = NULL` in the same transaction.
- **Audit:** one `source_config_changes` row per action, in the same
  transaction:

  | Action | `old` and `new` |
  |---|---|
  | `create` | `new` holds `{name, config}` |
  | `config` | `{name, config}`, both; written when the name or config changed |
  | `enable`, `disable` | null |

  - Append-only in `sql/roles.sql`.
  - Shown on `/admin/audit` with the newest 100 rows.
- **The Settings page** (`GET /admin/settings`, admin only) is read-only:
  connections, per-source last run and last failed crawl-job time, SSO,
  roles and MCP. A Settings tab goes first among the admin tabs.
- **The work is split three ways, as the requester asked:** me, agy and
  Codex. This overrides the default `coder` handoff. I commit every step.

## Steps

### Step 1 (me): validator, routes, schema and grants

**Files:**
- `app/sources.py`
- `sql/schema.sql`, after `source_acl_changes` (~`:222`)
- `sql/roles.sql`, after `:26`
- `tests/test_sources.py`, `tests/test_models_admin.py`

**Changes:**
1. **`parse_config(kind, *, bucket="", prefix="", include_ext="",
   tenant_id="", drive_id="", base_url="", spaces="", api_prefix="/wiki",
   staff=False) -> dict`.**
   - It raises `HTTPException(400, <field message>)`.
   - A helper `scope(kind, ...)` validates only the editable fields. Edit
     reuses it.
   - Delete `REQUIRED` and the inline Confluence check.
2. **`create()`:**
   - The `config` form field is replaced by the typed `Form("")` fields
     plus `staff: bool`.
   - It calls `parse_config` and inserts as before.
   - It writes the `create` audit row through a new
     `log_config_change(conn, sid, action, old, new, who)`.
3. **`update()`:**
   - Add `name: str | None = Form(None)` and each scope field as
     `Form(None)`.
   - After `for update`, read `name`, `config` and `enabled` too.
   - The first statement in the transaction is the xact lock. If it's
     taken, return the refuse response.
   - Merge the validated scope fields over the stored config, keeping the
     other keys and the root. Set `cursor=NULL` when a scope key's value
     changed.
   - Write the `config` row when the name or config changed, and the
     `enable`/`disable` row when `enabled` flipped.
   - Add `"crawling": ("bad", "A crawl is running for this source; try
     again when it finishes")` to `NOTICES`.
4. **Schema:** `create table if not exists source_config_changes (id
   bigserial primary key, source_id bigint not null, action text not null
   check (action in ('create','config','enable','disable')), old jsonb,
   new jsonb, changed_by text not null, changed_at timestamptz not null
   default now());`
5. **Grants:** `revoke update, delete on source_config_changes from
   refs_app;`
6. **Tests:**
   - Move the five old posts to typed fields.
   - Add:
     - `parse_config` accept and refuse cases, one per rule
     - create writes one `create` row
     - edit: scope changes, root fields posted but ignored, cursor reset,
       one `config` row
     - edit with no scope fields: config and cursor unchanged
     - an upload source's prefix and `staff` survive an edit
     - enable/disable rows
     - lock held on a second connection: 409, and the row is unchanged

**Verify:**
```bash
docker compose build app && docker compose run --rm app pytest tests/test_sources.py tests/test_models_admin.py
```

**Negative controls:**
- comment out the lock check: the lock test must fail
- let `parse_config` pass through `token=…` (temporary `**extra`): the
  "only named keys" test must fail

Record both results in this plan.

**Traps:**
- Build the app image before pytest, or a stale image is tested.
- Never run two `docker compose run` at once in one worktree.
- The xact lock must come before `select … for update`. A crawler holding
  the session lock doesn't hold row locks, but take the cheap refusal first.
- `executed_contracts` handling and ACL propagation stay byte-identical.

  - `GET /admin/settings`, `require("admin")`, rendered with `page()`.

    - the listed non-secret variables
    - a dict `{name: bool}` for the secrets (`GRAPH_CLIENT_SECRET`,

## Rollback

Revert the PR's merge commit. The `source_config_changes` table stays,
unused and harmless; `create table if not exists` makes re-applying safe.
Configs created through the typed form use only keys the crawlers already
read, so they keep working after a revert.

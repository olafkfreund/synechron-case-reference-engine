# Plan: Local demo with persistent made-up data

## Approved decisions (self-contained)

- **The command:** `scripts/demo.sh up | reset | down`, with compose project
  `refsdemo` and `-f docker-compose.yml -f docker-compose.demo.yml`.
  - `up`: build, start `web` and `worker`, wait for `/healthz`, run the seed,
    print the URL and the users.
  - `reset`: `down -v` for `refsdemo` only, then `up`.
  - `down`: stop the project and keep the data.
  - Ports stay `127.0.0.1:8000`/`8080`. If 8000 is taken, the script stops
    with a message.
- **Override `docker-compose.demo.yml`:**
  - `db` gets the named volume `pgdata` at `/var/lib/postgresql/data`;
  - `web` and `worker` get `env_file: [{path: .env.demo, required: false}]`.
  - The base compose file and CI are unchanged.
- **`.env.demo`** (committed, no secrets): `EXTRACT_MODEL` and `DRAFT_MODEL`
  set to `ollama_chat/qwen3:14b`, and both `*_OPTIONS` set to
  `{"think": false, "num_ctx": 24576, "repeat_penalty": 1.05, "api_base":
  "http://host.docker.internal:11434", "destination": "local"}`. If
  `curl -s localhost:11434/api/tags` fails, `demo.sh` starts with
  `DEMO_NO_MODEL=1`, which blanks the model settings, and says what needs a
  model.
- **S3:** moto stays in memory; the seed re-puts every demo original on each
  `up` (`put_object` is idempotent).
- **Seed data**, all made up, in one file `demo/cases.json`. Each entry has:
  - `source`, `file` and `paragraphs`: the document text, written as a
    `.docx` at seed time, so no binary files are committed;
  - `case`: a `ReferenceCase` whose `source_quote`s are copied verbatim
    from `paragraphs`;
  - `status`: `approved` or `extracted`.

  It also holds `sources` (two upload sources: "Bid library", groups
  `sales`, prefix `uploads/`; "Delivery archive", groups `delivery`, prefix
  `delivery/`) and `clients` (aliases, label, referenceable, logo).
  - Fictional names only: Contoso, Northwind, Fabrikam, Woodgrove,
    Tailspin, Litware, Adventure Works, Wide World Importers, Proseware,
    Alpine Ski House.
  - **12 cases:** 9 approved, 3 extracted (one with an outcome named
    "metric", one with an unsourced field, one ordinary), plus a Fabrikam
    SOW and change order as two `engagement` cases with the same client,
    left `extracted` so they can be merged (#55).
- **`scripts/seed_demo.py`** runs in `web` via `docker compose exec`. For
  each entry:
  - build the `.docx`, put it to `S3_BUCKET` at `<prefix><file>`, then
    `ingest.to_markdown()` (Docling, no LLM);
  - upsert the source, documents, cases and clients, keyed by `(source
    name, external_id)` and client name;
  - run `check(case, text)`, `fix_summary()` and `case.search_text()`, then
    set the status (`approved` with `review_due = now() + 12 months`,
    `approved_by='demo-seed'`, and `client_id` resolved as `approve` does).

  A second run re-puts S3 and leaves rows that already exist alone. It never
  touches rows it didn't create (all its sources are named `Demo: …`).
- **README `## Local demo`:** the commands, users, what needs a model, and a
  5-part walkthrough (sales, reviewer, admin, live upload, nobody).
- **Coder handoff:** 6 file-editing steps in 7 files, so steps 1–6 go to
  the `coder` agent. The session model does step 7 and the review.

## Steps

   `python3 -c "import json; d=json.load(open('demo/cases.json')); print(len(d['cases']))"`
   giving 14 (12 cases plus 2 contracts), and every quote being a substring
   of its entry's joined paragraphs: a one-off check in the same command.
   Traps: made-up names and numbers only, never from the presale folder;
   quotes must be verbatim; numbers in a value must appear in its quote
   (the app's `sourced()` rule).

   *Done (coder):* 14 entries (9 approved, 5 extracted, including the
   Fabrikam pair). Every planned quote passes the app's `sourced()`, and the
   deliberately unsourced field fails it. *Deviation:* the sources are
   named "Demo: Bid library" and "Demo: Delivery archive". Keys:
   `clients[]` = `name`, `aliases`, `label` (→ `anonymised_label`),
   `referenceable`, `logo`; `sources[]` = `name`, `groups`, `prefix`.

2. **`scripts/seed_demo.py`.** As decided. It reuses
   `app.ingest.to_markdown`, `app.extract.check`, `app.review.fix_summary`
   and `app.anonymise.resolve`/`load_clients`. Its entry point is
   `main() -> int`. → verify in step 5's test.
   Traps:
   - build the `.docx` with `python-docx` (already installed);
   - `to_markdown` needs the file name with `.docx`;
   - document `acl_groups` must equal the source's (the #58 repair copies
     them);
   - no LLM calls.
3. **`docker-compose.demo.yml` and `.env.demo`.** → verify by
   `docker compose -f docker-compose.yml -f docker-compose.demo.yml config -q`.
   Traps: don't edit `docker-compose.yml`; `app` gets nothing from the
   override.

   *Done (coder, steps 2 and 3 in one commit):* `config -q` passes. The
   seed compiles, and its test is step 5. The `.docx` bytes are
   deterministic (zip timestamps pinned), so a rerun keeps the checksum and
   a crawl doesn't see a change. *Deviation:* the override doesn't use
   `env_file`, because the base file's `environment: EXTRACT_MODEL:
   ${EXTRACT_MODEL:-}` would win over it. The model settings come in through
   `--env-file .env.demo` on every compose call in `demo.sh`. For
   `DEMO_NO_MODEL=1`, the script exports the four variables as empty
   strings, since shell values beat `--env-file`. So the override only adds
   the `pgdata` volume.

4. **`scripts/demo.sh`** (bash, `set -euo pipefail`, executable). →
   verify by `bash -n scripts/demo.sh` and `shellcheck` if available.
   Traps:
   - **never** run it during implementation: the user's `refsdev` demo is
     live on the same ports;
   - only `-p refsdemo` is ever used;
   - `reset` asks for no confirmation, but only touches `refsdemo`.
5. **`tests/test_seed_demo.py`:** with moto S3 (as `tests/test_ingest.py`'s

   - the second run adds no rows;
   - the Fabrikam pair is two `engagement` cases with one client.

6. **README `## Local demo`** after `## Local login (test users)`. →

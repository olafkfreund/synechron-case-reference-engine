# Plan: User guide for bid team, reviewers and admins

## Approved decisions (self-contained)

- **Readers:** bid team (user role), reviewers, admins. Not developers. Admins also hold the
  reviewer and user roles, and reviewers also hold the user role (`roles_for()` in `app/main.py`).
- **Docs only.** No change to `app/` (routes, templates, CSS) or to existing tests. New files:
  `docs/user-guide/{README,bid-team,reviewers,admins}.md`, `docs/user-guide/img/*.png`,
  `scripts/guide_screens.sh`, `tests/test_user_guide.py`; plus one line in the top-level `README.md`.
- **Page shape:** short task sections, each with three parts in this order: **What it's for**,
  **Steps**, **What you see**. Describe what a role can do, never how access checks work.
- **Labels:** every button, label, heading and tab is quoted exactly as `app/templates/*.html`
  renders it, in `**bold**`. Bold is used for UI labels only, apart from a short allow-list of
  non-label emphasis kept in the test (the three part names above, and "Which page is mine:").
- **Public repo:** made-up examples only. No client names, people, hosts or URLs except
  `localhost` and the demo's fictional companies. Upload example uses a made-up file name.
- **Screenshots:** 8 PNGs, 1280×900, demo data only, made from project `refsdemo`
  (`scripts/demo.sh up`), never refsdev or a real deployment. No research preview or result shot.

  | File | Demo user | Page |
  | --- | --- | --- |
  | `search.png` | `sales` | `POST /search` with `bid_text=payments` |
  | `research.png` | `sales` | `/research` |
  | `review-queue.png` | `reviewer` | `/review` |
  | `review-case.png` | `reviewer` | `/review/<id>` of a seeded `extracted` case with an unsourced field |
  | `sources.png` | `admin` | `/admin/sources` |
  | `clients.png` | `admin` | `/admin/clients` |
  | `models.png` | `admin` | `/admin/models` |
  | `audit.png` | `admin` | `/admin/audit` |

- **Screenshot script** `scripts/guide_screens.sh`: logs in through the mock IdP with curl and a
  cookie jar (as `scripts/check_local_login.sh`), fetches each page, inserts
  `<base href="http://localhost:8000/">` after `<head>`, saves to a temp file, then
  `chromium --headless --window-size=1280,900 --screenshot=<png> file://<tmp>`. Refuses unless
  `BASE` is `http://localhost:8000` (or another `localhost` URL). Never starts or stops compose. No
  new dependency (no Playwright/Selenium).
- **No CSRF tokens:** the app's guard checks the `Origin` header on POST against `APP_ORIGIN`
  (`app/main.py:121-124`). The search POST must send `-H 'Origin: http://localhost:8000'`
  (i.e. `$BASE`), otherwise it gets 403 `cross-origin request refused`.
- **Screenshots are made by the session model**, not the coder, against the running demo the user
  started. The coder writes the script but does not run it against a server.
- **Test** `tests/test_user_guide.py`, part of the normal suite:
  - link check: every relative Markdown link/image in `docs/user-guide/*.md`, and the README guide
    link, points to an existing file;
  - label check: every `**…**` span in the guide pages, minus the allow-list, appears verbatim in
    some `app/templates/*.html`, after `html.unescape` of the templates, with each Jinja
    `{{ … }}` treated as a wildcard (`.*?`) and `{% … %}` removed.
- **README:** one line under `## Links`: `- [User guide](docs/user-guide/README.md): how to use the
  portal, per role`.
- **Risk accepted:** screenshots can go stale silently; re-run the script when a main page's
  layout changes. Upload has no UI, so the admin page documents `POST /admin/upload`.

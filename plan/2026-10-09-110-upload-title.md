# Plan: Uploaded documents are titled with the stored key, not the file name

Approved decisions (spec):

- **Key layout:** upload stores each file at `{prefix}{uuid}/{name}` instead of
  `{prefix}{uuid}-{name}`. `name` is the result of `safe_name()`.
- **No crawler change:** `app/crawl.py:62` already titles each document with
  `key.rsplit("/", 1)[-1]`. That is now `name`, the extension upload
  validated included, which `to_markdown` needs.
- **Why it holds:**
  - `safe_name()` (`app/main.py:75-79`) maps everything outside
    `[A-Za-z0-9._-]` to `_`, so `name` never contains `/`.
  - The uuid keeps same-name uploads apart.
  - `crawl_s3` lists by prefix with no `Delimiter`, so keys one level deeper
    are still found.
  - Upload never writes a key ending in `/`, so the folder-marker skip
    (`app/crawl.py:46`) doesn't drop these objects.
  - `external_id` stays the full key, so document identity and deletion
    detection don't change.
- **No backfill:** documents already uploaded keep their old titles.
  `scripts/demo.sh reset` clears the one demo document.
- **IAM unchanged:** the grant is `s3:PutObject` on
  `${originals}/${var.upload_prefix}*` (`infra/iam.tf:91-94`). In IAM, `*`
  also matches `/`. No `infra/` edit.

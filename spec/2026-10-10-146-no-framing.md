# Spec: No portal page can be framed by another page

## Design

All changes are in `app/main.py`.

1. Add one module constant next to `SAFE_METHODS` (`:24`):

   ```python
   # clickjacking: a sibling subdomain could frame /review and borrow a reviewer's click (#146)
   NO_FRAME = {"X-Frame-Options": "DENY", "Content-Security-Policy": "frame-ancestors 'none'"}
   ```

2. Change `guard` (`:121-134`) so every response gets these headers:
   - Its two early refusals (the 403 for a cross-origin request and the 413
     for an oversize body) assign to `response` instead of returning.
   - Otherwise `response = await call_next(request)`.
   - `response.headers.update(NO_FRAME)`, then `return response`.

   `guard` is the outermost middleware, because it is added after
   `SessionMiddleware`. So these responses all pass through it:
   - every route, including `/healthz`;
   - the `StaticFiles` mount;
   - the 401 handler's redirect to `/login`;
   - FastAPI's error responses.

Both headers are sent:
- `frame-ancestors 'none'` is the current standard.
- `X-Frame-Options: DENY` covers older browsers.

The CSP carries only `frame-ancestors`, so it restricts nothing else: no
script, style or font rules that could break a page.

## Alternatives rejected

- **Set the headers on the ALB** (`infra/alb.tf`, response header
  modification). The protection would then depend on the deployment, and local
  and test runs would go without it. The app setting them is one place, and
  it can be tested.
- **`SAMEORIGIN` / `frame-ancestors 'self'`.** No portal page frames
  another, as the intent says, so `'none'` is the tighter setting at the
  same cost.
- **A full CSP (`default-src 'self'` and so on).** It is worth doing, but it
  is a separate change with its own risk to fonts, inline styles and
  downloads. This issue is about framing only.
- **A frame-busting script.** The portal runs no JavaScript, and headers are
  the robust fix anyway.
- **`SameSite=strict` on the session cookie.** It doesn't stop framing from a
  sibling subdomain, because that request is same-site. It would also break
  the sign-in redirect back from the IdP.

## Risks

- **Something embeds a portal page.** Nothing does today, as the intent says.
  If an embed is ever needed, that page relaxes the header for itself.
- **A response that bypasses `guard`:**
  - Starlette's outermost `ServerErrorMiddleware` returns its plain 500
    without these headers.
  - That page has no form and no session action, so it is harmless to frame.
- **A future route that sets its own CSP** would be overwritten by
  `headers.update`. There is none today. If one is ever added, it should
  merge in `frame-ancestors` rather than replace the policy.

## Verification

- New `tests/test_hardening.py::test_every_response_refuses_framing` must fail
  on main's `app/main.py`. It asserts that both headers, with exactly the
  values above, are on:
  - an anonymous `GET /healthz` (200);
  - `GET /static/portal.css` (200);
  - an anonymous `GET /review` with `Accept: text/html` (the 303 to
    `/login`);
  - a reviewer's `GET /review` (200);
  - a cross-origin `POST` refused by `guard` (403), using a client built
    with `client([REV], origin="http://evil.example")`.
- The full suite passes.

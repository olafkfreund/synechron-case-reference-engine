# Spec: research says why sources were skipped

## Design

The worker already stores one entry per skipped source:
`{"domain": host, "error": type(e).__name__}` (`app/research.py:840`). Only
the exception class name is used. It is mapped to a plain reason when the
page is drawn, so nothing new is stored and older rows read as they are.

**1. A mapping in `app/research.py`, next to the error classes:**

| Stored `error` | Shown reason |
|---|---|
| `RobotsDisallowed` | don't allow automated access |
| `Stalled`, `ConvertTimeout`, httpx `*Timeout` | didn't respond in time |
| httpx `ConnectError`, `RemoteProtocolError`, other httpx errors | couldn't be reached |
| `TooLarge` | too large |
| `BadContentType`, `ConvertFailed` | not a web page or PDF |
| `ResearchError` (an HTTP 4xx/5xx status) | refused by the server |
| `Blocked` | not a public address |
| anything else | other errors |

- **`Blocked` is wider than its label.** It is also raised for a host that
  doesn't resolve, a non-http(s) URL, an unusual port and too many redirects
  (`research.py:329-351`, `:445`). These are all our safety checks refusing
  the fetch, so the label is **"blocked by our safety checks"** instead of
  "not a public address". This is the one change from the intent's list.
- **A stalled body read is miscounted today.** `research.py:465` raises a
  plain `ResearchError("fetch took too long")`, which would read as "refused
  by the server". It becomes `Stalled`, as at `:370`. `Stalled` subclasses
  `ResearchError`, so every existing `except` still catches it.

**2. `research_view` groups the reasons** (`research.py:250`). It passes
`skip_reasons`, a list of `(reason, count)` pairs, largest first, built from
`skipped`. The hidden-source placeholders `{}` (`:250`) have no `error`. They
count toward the total but get no reason, so a hidden source never shows
why.

**3. The template line** (`research_view.html:63`) becomes, for example:

> 8 source(s) skipped: 6 don't allow automated access, 2 didn't respond in time.

When every skipped source is hidden, the line stays "8 source(s) skipped."
as today. The `domain` is never passed to the template.

## Alternatives rejected

- **Store a reason code per entry.** It would be more precise for `Blocked`,
  but older rows would still need the class-name mapping, and the intent
  rules out new data.
- **List each skipped domain with its reason.** A domain can name a client.
  The intent forbids it.
- **Show the exception message.** The messages are safe (`ResearchError`
  docstring), but they're technical ("HTTP 403") and the class name already
  carries the reason.

## Risks

- **An unknown or new class name shows "other errors".** It can't fail the
  page.
- **A test asserts the exact current text** ("1 source(s) skipped." in
  `tests/test_research_claims.py:195`). Its rows hold one hidden page, so the
  text stays the same; the test is kept as the check for hidden sources.
- **No crawler, worker or schema change** apart from the one-line `Stalled`
  fix. That fix changes only the class name stored for that one case.

## Verification

- **Route test** (`tests/test_research_claims.py`): a stored row with
  skipped entries `RobotsDisallowed` ×2, `Stalled`, `Blocked` and an unknown
  class shows "5 source(s) skipped: 2 don't allow automated access, 1 didn't
  respond in time, 1 blocked by our safety checks, 1 other errors". No
  domain appears in the HTML.
- **Hidden source:** the existing test still shows "1 source(s) skipped."
  with no reason.
- **Worker test** (`tests/test_research.py`): a body read past the deadline
  is stored as `Stalled`.
- **Full suite:** `docker compose build app && docker compose run --rm app
  pytest`.
- **Demo:** run the SAP question from the issue, and screenshot the Sources
  line.

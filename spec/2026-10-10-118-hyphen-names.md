# Spec: A hyphenated client name is not matched when written with a space or run together

## Design

`_pattern` (`app/anonymise.py:33-37`) is the one place every matcher builds its
regex. The change splits the registered name on whitespace and dashes alike,
so the separators already inside a name get the same `_JOIN` treatment that
the separators between its words do today:

```python
_SEP = r"[\s\-‐‑–—]"
_JOIN = _SEP + "*"

def _pattern(name: str) -> re.Pattern:
    words = [w for w in re.split(_SEP + "+", name) if w] or [name]  # "-" alone stays literal, never empty
    body = _JOIN.join(re.escape(w) for w in words)
```

- **One registered name, every form.** "Zorp-Tek", "Zorp Tek", "ZorpTek" and
  "Zorp–Tek" now produce the same pattern, so each matches all four.
- **The four functions.** `apply`, `blocked`, `has_name` and `scrub` all go
  through `_pattern`, so they all change together.
- **The fallback.** `or [name]` covers a name that is only dashes. Without it,
  the body would be empty, and an empty pattern matches at every word
  boundary. `clients.clean` already refuses empty names, but `_pattern` should
  not depend on that.

## Alternatives rejected

- **Normalise dashes to spaces when a client is saved.** That fixes only new
  saves, and it changes what the admin typed. Fixing the pattern covers
  existing rows too.
- **Only replace `-` and keep the Unicode dashes literal.** "Zorp–Tek", with
  an en dash from Word autocorrect, would still leak. `_JOIN` already lists
  the dashes, and `_SEP` reuses that list.

## Risks

- **More matches only.** A name with no dash builds exactly the same pattern
  as before, because `re.split` on whitespace gives the same words as
  `.split()`. A dashed name matches a superset of what it matched before.
- **#119 touches the same function.** It changes the flags line, two lines
  down. Whichever merges second rebases onto the other, and the conflict is
  trivial.
- **No host impact.**

## Verification

- A new test in `tests/test_anonymise.py`. For protected "Zorp-Tek",
  `apply()` maps "Zorp Tek", "ZorpTek", "Zorp–Tek" and "Zorp-Tek" each to the
  label, and `blocked()` of the output is `[]`. Without `apply()`,
  `blocked()` finds each form. The test fails on main.
- A test that a name made only of dashes does not match plain text.
- The existing anonymise tests and the full suite pass.

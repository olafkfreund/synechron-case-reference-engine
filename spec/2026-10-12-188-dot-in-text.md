# Spec: A protected name written with a dot the registry doesn't have leaks into downloads

## Design

This carries over the user's decision of 2026-10-12, recorded in the intent:

- A dot after any word of a registered name is optional.
- Dots inside letters are not optional. "US Bank" still doesn't match
  "U.S. Bank" (the #163 rule).
- A sentence break like "Zorp. Co-founders" being hidden is accepted.

The change is one line in `_pattern` (`app/anonymise.py:56-60`). Between two
words, the joiner allows an optional dot before the usual separators:

```python
join = r"\.?" + _JOIN if loose is _loose else _JOIN
body = join.join(loose(re.escape(w)) for w in words)
```

With "St James's Bank" registered, the pattern becomes
`St\.?[sep]*James['’…]s\.?[sep]*Bank`. That matches "St. James's Bank",
"ST. JAMES'S BANK" and "St.James's Bank". `apply()`, `blocked()`, `has_name()`
and `scrub()` all build their patterns with `_pattern`, so all four change
together. `blocked()` keeps matching at least what `apply()` replaces, so the
check still fails closed.

**The last word needs nothing new.** With "Zorp Co" registered, the text
"Zorp Co." already matches "Zorp Co": the dot is not a word character, so the
end lookaround holds. The dot then stays as text, giving "a firm." rather than
"a firm". So "after any word" holds for matching, and the full stop that ends a
sentence is kept. The existing assert at `tests/test_anonymise.py:153` keeps
passing ("Zorp, Inc. said" → "a firm. said").

**Dotted initials are still kept apart.**
- "US" compiles to `US\.?`, so it needs the letters "us" next to each other.
  "U.S." puts a dot between them and doesn't match.
- A registry "U.S." (inner dots) still doesn't match text "us"
  (`test_anonymise.py:156`). `_loose` is unchanged.

This only touches the joiner in `_pattern`. #187 edits the same file in
parallel, in `_no_format`/`fold` per its issue. The two hunks should not
overlap. Whichever lands second rebases.

## Alternatives rejected

- **Append `\.?` to every word in `_loose`:** it would also cover the last
  word, and the match would swallow the full stop that ends a sentence:
  - "We worked with Zorp Co. They…" would become "…a firm They…".
  - It would change the existing `:153` expectation.
- **Strip all dots from the text and the names before matching:** "U.S."
  would then match "us", which #163 refused. It would also break the `at`
  index mapping in `_replace_once`.
- **Ask admins to add dotted aliases:** this is the status quo. Every
  abbreviation leaks until someone notices.

## Risks

- **More hidden text, never less:**
  - A sentence break between two words of a name now matches, as in
    "…with Zorp. Co-founders…" (accepted).
  - The same goes for a dotted join with no space, like "zorp.co.uk" when
    "Zorp Co" is registered. That becomes "a firm.uk", which is in line with
    how emails and joined names are already hidden.
  - Downloads may be withheld more often only where `blocked()` now finds a
    name that `apply()` also replaces. So no new 409s are expected.
- **Names with no word characters** (for example "-") are untouched, because
  `loose is str` keeps the plain joiner.
- **Runtime:** one optional character per join, which costs nothing
  measurable.

## Verification

Add a new test to `tests/test_anonymise.py`, `test_dot_after_a_word_in_text`,
using made-up names. These cases fail on main:

- `apply("We helped St. James's Bank", [C("St James's Bank", label="a bank")]) == "We helped a bank"`
- `blocked("ST. JAMES'S BANK", …) == ["St James's Bank"]`
- `"james" not in scrub("core banking for St. James's Bank", …)`
- `blocked("Zorp. Co", [C("Zorp Co")]) == ["Zorp Co"]`
- `apply("with Zorp Co. They", [C("Zorp Co", label="a firm")]) == "with a firm. They"`.
  This one passes on main; it guards the last-word rule.

These pass on main and must keep passing:

- `blocked("U.S. Bank", [C("US Bank")]) == []`
- `blocked("us bank", [C("U.S. Bank")]) == []`
- `blocked(apply(t, reg), reg) == []` for each spelling above.

Then run the full suite (`docker compose build -q app && docker compose run --rm app pytest -q`). All tests must pass, including `test_punctuation_variants_of_a_name`.

# Spec: Case cards link to their source documents and folders, safely

## Design

### 1. Storage (`sql/schema.sql`)

Two nullable columns, added idempotently:

```sql
alter table documents add column if not exists web_url text;
alter table documents add column if not exists folder_url text;
```

Null means "no link" (uploads, S3 and DataSync shares, or not crawled
since this change). Nothing else changes: no new table and no index (the
card query reads by `document_id`).

### 2. Capture in the crawlers (`app/crawl.py`, `app/ingest.py`)

- **`ingest()` and `skip_unchanged()`** take an optional
  `links: tuple[str | None, str | None] = (None, None)`, meaning
  `(web_url, folder_url)`.
  - They write both columns in the new-version upsert and in the same-bytes
    update.
  - `skip_unchanged` writes them in its existing `update`.
  - So an unchanged item gets its links on the next crawl, with no new
    version and no download.
  - The S3 crawler and upload pass nothing, so their documents stay null.
- **SharePoint (`handle()`):**
  - `web_url` is `item["webUrl"]`.
  - `folder_url` is the parent's `webUrl`. Delta items carry
    `parentReference.id`, so the crawler fetches
    `items/{parent}?$select=webUrl` once per parent id, cached for the
    run. Don't derive it from the file URL, because Office files can come
    back as `Doc.aspx?sourcedoc=…` links.
  - The allowed host is read once per crawl from
    `GET drives/{drive}?$select=webUrl`. The crawl already makes per-drive
    calls, so this adds one.
- **SharePoint backfill.**
  - Delta only re-offers changed items.
  - The existing live re-check loop already calls `perms_of(items/{iid})` for
    every live document. For live documents whose `web_url is null`, it
    also calls `items/{iid}?$select=webUrl,parentReference` once and writes
    the links.
  - That's one call per document, once ever.
- **Confluence:**
  - A page's `web_url` is `base + page["_links"]["webui"]`, where `base`
    is the client's own `c.base`, never `_links.base`. An attachment links to
    its page. Pages carry the link in every expand the crawler already
    uses.
  - `folder_url`: for a page, its parent page (the last ancestor's webui,
    when the ancestor is present in `expand=ancestors`); for an attachment,
    its page. The allowed host is the configured `base_url`'s host.
- **Confluence backfill.** The existing re-check loop already fetches
  `content/{pid}?expand=ancestors,space` for every live document, so it
  writes the links there when they're missing.
- **Validation, in a `safe_link(url, host)` helper in `crawl.py`.**
  - It keeps the URL only when:
    - the scheme is `https`
    - the host equals the allowed host exactly
    - it has no user or password part
    - it's at most 2,000 characters
  - Otherwise it stores null. A bad link loses the link, not the document.

### 3. The card's data (`app/search.py`)

- **One extra query per result page,** not per row: `source_docs(case_ids,
  user)`. For each case id it returns its live, visible documents: for a
  merged case, every member's document (`m.id = c.id or m.merged_into =
  c.id`), with `d.title`, `d.web_url`, `d.folder_url` and the source name.
- It uses the same conditions as `VISIBLE`: `deleted_at is null and
  acl_groups && user.groups`. Because `VISIBLE` already requires every member
  of a shown case to be live and visible, the list never shows something
  the case filter would hide.
- `view()` gains `sources=[…]`, which `browse()` and `results()` both pass.

### 4. Titles and visibility rules

| Who | Client of the case | Shown per document |
|---|---|---|
| reviewer or admin | any | `clean(title)` and links |
| user | linked and referenceable | `clean(title)` and links |
| user | protected, unlinked or unknown | no title: "1 document in <source>" (or "N documents"), plus links |

- `clean()` is the existing `apply()` plus a `blocked()` fallback. A title
  that still leaks shows as "[withheld]".
- The links stay for plain users even when the title is hidden: the target
  is the source system, which enforces their own access.
- Source names are admin-chosen labels ("Demo: Bid library") and are shown
  as they are, as on the Sources page.

### 5. Template (`search.html`)

- **A collapsed "Source documents (N)" disclosure on each card,** in both
  the browse rows and the ranked results.
- For each document: the title or the count text, then "Open" (`web_url`)
  and "Open folder" (`folder_url`).
- Links render only when the value is non-null, as
  `<a href="{{ url }}" target="_blank" rel="noopener noreferrer">`, and are
  autoescaped.
- A document with no links shows "stored in the engine; ask a reviewer".
- The URL itself is never shown as text.

## Alternatives rejected

- **Serve the engine's stored copy:** it bypasses the source's own
  permissions and the commercial and protected-name stripping.
- **A folder browser through the crawler's credentials:** it shows files the
  user may not be allowed to see. "Open folder" lets the source enforce
  that.
- **Derive the folder from the file URL:** this breaks on SharePoint
  `Doc.aspx` links.
- **Fetch links at view time:** it needs per-user source calls and new
  credentials, which the intent rules out.

## Risks

- **Open redirect or phishing.**
  - Links are only stored from the source API's own fields, after
    `safe_link`'s exact host match against the drive's or the configured
    base's host.
  - A forged `_links.base` or a cross-host `webUrl` is dropped.
- **Client names in URLs.** A SharePoint path can contain a protected
  client's name, but it's only the `href`, never shown as text. The user
  already has source access by group mapping, and the link never appears in
  any customer output (render paths don't read these columns). This is
  accepted, as the intent says.
- **Titles leaking:** covered by the rules in section 4 and `clean()`.
- **Backfill cost:** one SharePoint metadata call per live document, once.
  Confluence needs no extra calls.
- **Stale links after a move:** SharePoint delta re-offers moved items, so
  their links are refreshed on the next crawl.

## Verification

- `tests/test_crawl_sharepoint.py`:
  - A fake Graph returns `webUrl` and `parentReference`; the links are
    stored.
  - A cross-host or `http` `webUrl` is stored as null.
  - The parent lookup is cached once per parent.
  - A live document with null links gets them through the re-check, without
    a new version.
- `tests/test_crawl_confluence.py`:
  - A page and an attachment get page links from `c.base`, never from
    `_links.base`.
  - A forged `_links.base` host is ignored.
  - The backfill works through the re-check.
- `tests/test_search.py`:
  - A user with a referenceable client sees the titles and links.
  - A protected client shows the count text, with the links and no title.
  - A reviewer sees titles.
  - A merged case lists every member.
  - A withdrawn or invisible document never appears.
  - Uploads show "stored in the engine; ask a reviewer".
  - Hrefs are escaped and carry `rel="noopener noreferrer"`.
- **Full suite:** `docker compose build app && docker compose run --rm app
  pytest`, run alone.

# Spec: a Settings page for crawl configuration, connection and SSO status

## Design

Three parts:

1. Typed, editable, audited crawl configuration on the existing Sources page
2. A new read-only Settings page
3. One new audit table

There is no new settings store. Every value still comes from where it lives
today: environment variables or the `sources` row.

### 1. Crawl configuration (`app/sources.py`, `app/templates/sources.html`)

**Fields per kind.** These are the keys the crawlers read today
(`app/crawl.py:51,57,202,204,420,424`, `app/main.py:328`,
`app/ingest.py:97`):

| Kind | Root, fixed after creation | Scope, editable | Other |
|---|---|---|---|
| `s3` | `bucket` | `prefix`, `include_ext` | `executed_contracts` |
| `upload` | `bucket`, `prefix` | `include_ext` | `staff`, `executed_contracts` |
| `sharepoint` | `tenant_id`, `drive_id` | `include_ext` | `executed_contracts` |
| `confluence` | `base_url` | `spaces`, `api_prefix` | `executed_contracts` |

- **An upload source's `prefix` is part of its root.** Staff uploads are
  written under it (`app/main.py:328`), and the S3 sweep withdraws every
  live key outside the listing (`app/crawl.py:87-97`). Changing it would
  withdraw every uploaded document.
- **`staff` can be set at creation and is shown, but not edited here.**
  Which upload source takes staff uploads is a separate decision (#249),
  outside this issue.

**One validator, `parse_config(kind, fields) -> dict`,** replaces
`REQUIRED` (`sources.py:48`) and the inline checks in `create()`
(`sources.py:124-133`). It takes the typed form fields, not JSON:

- **Unknown keys are impossible by construction:** the dict is built only
  from the named fields above. `config` can't hold a secret, because there
  is no field to put one in.
- `bucket`: the S3 bucket-name rules (3–63 characters, lowercase letters,
  digits, `.` and `-`).
- `prefix`: no leading `/`, no `..` segment, at most 1024 characters.
- `include_ext`: comma-separated, each matching `[a-z0-9]{1,10}` after
  lower-casing and stripping `.`. Empty means the crawler default
  (`docx, pptx, pdf`), which leaves the key out.
- `tenant_id`: a UUID. `drive_id`: `[A-Za-z0-9!_-]{1,200}`.
- `base_url`: `https://`, with a host, and no user info, query, fragment or
  port other than 443. Stored without a trailing `/`.
- `spaces`: one or more keys, each matching the existing
  `~?[A-Za-z0-9_-]+` (`sources.py:131`).
- `api_prefix`: `""` or `/wiki`.

**Create** (`POST /admin/sources`) keeps its route and adds the typed
fields:

- The `config` JSON form field is removed.
- It writes a `create` audit row.

**Edit:** `update()` (`POST /admin/sources/{sid}`) also accepts `name` and
the scope fields for the row's kind.

- **Root fields are never read from the edit form,** so they can't change.
  The root is taken from the stored config.
- **A running crawl refuses the edit:**
  - **The lock:** the edit transaction first runs
    `select pg_try_advisory_xact_lock(2, %s)`. That's the key every
    crawler holds for its whole crawl (`app/crawl.py:39,198,416`).
  - **If it's taken,** the edit redirects with a new allow-listed notice
    (`NOTICES`, `sources.py:19`): "A crawl is running for this source; try
    again when it finishes". It returns 409 for non-browser callers, the
    way the existing notices work.
  - **This blocks every edit while a crawl runs,** including ACL and
    enable/disable. That is wanted: the crawl copies the ACL to the
    documents at its end.
- **A scope change sets `cursor = NULL`** in the same transaction, so the
  next crawl is a full one. Measured against the crawlers:

  | Kind | Widening | Narrowing |
  |---|---|---|
  | S3 | lists everything on every run, so new keys are fetched anyway | the sweep withdraws keys outside the new scope (`crawl.py:87-97`) |
  | SharePoint | delta only offers changes, so a full delta is needed to see older files | the full delta withdraws unseen items (`crawl.py:323`) and type-skipped ones (`crawl.py:250-252`) |
  | Confluence | CQL `lastmodified` > cursor misses older pages in a new space, so a reset is needed | the recheck withdraws pages outside `spaces` (`crawl.py:450`, `:583-597`) |

  So the reset is necessary for SharePoint and Confluence, and harmless
  for S3. It is applied uniformly. The existing empty-listing guard
  (`crawl.py:98-101`) still stops a mistaken S3 prefix from withdrawing
  everything.
- **The form warns before save:** "Narrowing the scope withdraws documents
  outside it on the next crawl."
- **The ID is shown:** each row on Sources says "Source #id". That is the
  `source_id` in crawl jobs and in the advisory-lock key.

**Audit:** a new table `source_config_changes(id bigserial,
source_id bigint, action text, old jsonb, new jsonb, changed_by text,
changed_at timestamptz default now())`.

- **One row per create, config or name edit, and enable/disable,** written
  in the same transaction as the change.
- **`action`** is one of `create`, `config`, `enable` or `disable`.
- **`old` and `new`** hold `{name, config}` for create and config. They
  hold nothing for enable and disable.
- **ACL and data-class changes keep their own tables.**
- **`sql/roles.sql`:** `refs_app` gets insert and select, and update and
  delete are revoked, like `source_acl_changes` (`roles.sql:20`).
- **The table is shown on `/admin/audit`** (`app/audit.py`), next to the ACL
  and class changes, with the newest 100 rows.

### 2. Settings page (`app/settings.py`, `app/templates/settings.html`)

`GET /admin/settings`, `require("admin")`, rendered with `page()`
(`app/review.py`). It is read-only and has no forms. It reads only
`os.environ` and the `sources` table, with no network calls.

**Connections:**

| Connector | Shown | Secret: "Configured" or "Not configured" only | Changed in |
|---|---|---|---|
| SharePoint (Graph) | `GRAPH_CLIENT_ID` | `GRAPH_CLIENT_SECRET` | Terraform, Secrets Manager |
| Confluence | `CONFLUENCE_EMAIL` | `CONFLUENCE_TOKEN` | Terraform, Secrets Manager |
| S3 originals | `S3_BUCKET` | — | Terraform |
| Brave search | — | `BRAVE_API_KEY` | Secrets Manager |
| Models | `EXTRACT_MODEL`, `DRAFT_MODEL`, the Ollama base URL's scheme and host only | `OLLAMA_CLOUD_KEY` | Terraform, Secrets Manager |

- **The plan step confirms each variable name** against `infra/` and
  `app/` before use. Names that don't exist are dropped, not invented.
- **A secret's status comes from `bool(os.environ.get(name))`.** The value
  is never passed to the template: the view builds a dict of booleans.
- **`*_MODEL_OPTIONS` is never read.**
- **Per source:** the id, name, kind, enabled, `last_run_at`, the
  `last_counts` totals (new, updated, deleted, failed), and the time of the
  last failed crawl job. Error text and `failed_keys` are never shown.
- **Each source links to its row on Sources.**

**SSO:**

- **Login:** `OIDC_METADATA_URL` and `OIDC_REDIRECT_URI`, both as scheme,
  host and path only; `OIDC_CLIENT_ID`; `OIDC_GROUPS_CLAIM` (default
  `groups`); and whether the client secret is configured.
- **Roles:** for user, reviewer and admin, the groups from
  `ROLE_<ROLE>_GROUPS`, parsed by the existing `_env_groups`
  (`app/main.py:42`). The signed-in admin's own matching groups are marked.
- **MCP:** whether it is enabled (`MCP_ENABLED`); if so, `MCP_ISSUER`,
  `MCP_AUDIENCE`, `MCP_SCOPE` and `MCP_CLIENT_IDS`.
- **A notice** says these are set in Terraform and Secrets Manager, because
  a wrong value here could lock every admin out.

**Navigation:** a Settings tab, first among the admin tabs in
`app/templates/base.html`. Sources keeps its URL.

## Alternatives rejected

- **Editable SSO and secrets in the portal.** That needs a lockout-safe
  break-glass design, secret storage, IAM changes and a security sign-off.
  The requester decided it stays read-only.
- **Test-connection buttons.** They would make outbound requests from
  inside the VPC (an SSRF risk). They are a later phase with their own
  review.
- **A settings table in Postgres overriding the environment.** That gives
  two sources of truth, and the web and worker containers could disagree.
- **Keeping the raw JSON field with an allow-listed key check.** It still
  shows whatever is stored, and typed fields give better errors.
- **A cursor reset only where needed (SharePoint and Confluence).** It's
  one more branch for no benefit: S3 ignores the cursor for new keys, and
  the sweep runs either way.
- **Allowing root changes with a forced full crawl.** A changed bucket,
  drive or site is a different source. Reusing the row would mix two
  sources' documents and ACL history. To change a root, create a new
  source and disable the old one.
- **Per-source schedules and model selection.** EventBridge owns the
  schedule. Model choice must match the Bedrock IAM allowlist and be read
  the same by web and worker. Both are out of scope.

## Risks

- **Narrowing a scope withdraws documents on the next crawl,** and their
  cases with them, as for a deleted file today. Mitigations: the warning on
  the form, the audit row with the old config (so the change can be
  reverted), and the S3 empty-listing guard. Withdrawn documents come back
  when the scope is widened again.
- **Existing rows may hold keys the form doesn't know.** Edit merges only
  the scope fields into the stored config, so other stored keys are kept,
  not dropped. The page shows the typed fields only.
- **A long crawl blocks edits for its whole run.** That's by design. The
  notice says why.
- **Rendering configuration could leak.** Mitigations: secret values
  are never read into the view model, `*_MODEL_OPTIONS` is never read, and
  URLs are reduced to scheme, host and path (so tokens in a query string
  can't show). A test sets fake secrets and asserts they are absent from
  the HTML.
- **No host-specific risk.** The change touches the app and schema only;
  infrastructure is unchanged. The new table is created by
  `sql/schema.sql`, like the other audit tables.

## Verification

- **`parse_config` tests:**
  - every field rule, accepted and refused
  - the output holds only the named keys
  - a config with a `token` can't be produced
- **Route tests** (`tests/test_sources*.py`):
  - creating from typed fields stores the expected config and one
    `create` audit row
  - an edit changes the scope, keeps the root even when root fields are
    posted, resets `cursor`, and writes one `config` audit row with old and
    new values
  - enable and disable each write one row
  - an upload source's prefix and `staff` are unchanged by an edit
  - an edit while another connection holds `pg_advisory_lock(2, sid)` is
    refused (409 or notice), and nothing changes
- **Settings tests** (`tests/test_settings.py`):
  - 403 for reviewer and user, 200 for admin
  - with fake values in every secret variable, and in a `*_MODEL_OPTIONS`
    and an OIDC URL query string, none of them appears in the HTML
  - "Configured" and "Not configured" follow the environment
  - the admin's own groups are marked
- **Audit page test:** a config change shows on `/admin/audit`.
- **Negative controls, run once and recorded in `plan/`:**
  - without the lock check, the in-flight edit test fails
  - feeding the old JSON path a `{"token": …}` config shows the test
    catches a stored unknown key
- **Full suite:** `docker compose build app && docker compose run --rm app
  pytest`.
- **Demo:** `scripts/demo.sh up`. As admin:
  - open Settings
  - edit a demo source's prefix and see the audit row
  - run "Crawl now"
  - take screenshots in light and dark
- **Reviews:** Codex `review --base origin/main` (read-only), agy, and a
  fresh Opus reviewer on the diff against `plan/`.

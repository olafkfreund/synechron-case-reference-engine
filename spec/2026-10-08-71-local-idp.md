# Spec: Log in locally with test users

## Design

**Provider: navikt `mock-oauth2-server`** (intent question 1), pinned to
`ghcr.io/navikt/mock-oauth2-server:6.0.4`. I'm not using 6.0.5: it was
released today.

- It is a real OIDC provider: discovery, signed RS256 ID tokens, JWKS, and
  the code flow with state and nonce. So the app's own `/login` and `/auth`
  (authlib) validate it exactly as they would a company provider.
- With `interactiveLogin`, its login page has a **username** field and a
  **claims** box (JSON). The tester types a user name and pastes the groups,
  so switching users or groups is one logout and login away. There are no
  user accounts to maintain.
- It uses about 190 MB of memory and starts in seconds.

**One address for both sides: `idp.localhost:8080`** (intent question 2).
The mock server builds its issuer from the address it was called on, so the
browser and the app must call it at the same name and port.

- The browser resolves `*.localhost` to the loopback address (browsers and
  systemd-resolved do this for any `.localhost` name). It reaches the
  published port `8080:8080`.
- Inside compose, the `idp` service has the network alias `idp.localhost`,
  so the web container reaches the same server directly. This doesn't depend
  on `host-gateway` or the host firewall.
- Issuer, authorize and token endpoints are therefore all
  `http://idp.localhost:8080/refs/...`.

**`docker-compose.yml` changes:**

- A new `idp` service:
  - image pinned as above;
  - `ports: ["8080:8080"]` and the network alias;
  - `JSON_CONFIG: '{"interactiveLogin": true}'`.
- `web` gets:
  - `depends_on: idp`;
  - `OIDC_METADATA_URL=http://idp.localhost:8080/refs/.well-known/openid-configuration`;
  - `OIDC_CLIENT_ID=refs-local` and `OIDC_CLIENT_SECRET=dev-only-not-a-secret`.
    The mock server accepts any client, and the names say they are fake;
  - `ROLE_USER_GROUPS=refs-users`, `ROLE_REVIEWER_GROUPS=refs-reviewers`
    and `ROLE_ADMIN_GROUPS=refs-admins`.
- No profile is needed. `docker compose up web worker` starts the provider
  through `depends_on`. CI runs `docker compose build` (`idp` has no build)
  and `docker compose run --rm app pytest` (`app` doesn't depend on `idp`),
  so CI is unchanged.

**README, `## Local development`:** start with `docker compose up web
worker`, open http://localhost:8000, then sign in with one of these:

| Username | Claims to paste | Gets |
| --- | --- | --- |
| `admin` | `{"name": "Test Admin", "groups": ["refs-admins"]}` | admin, reviewer, user |
| `reviewer` | `{"groups": ["refs-reviewers"]}` | reviewer, user |
| `sales` | `{"groups": ["refs-users", "sales"]}` | user, and documents of sources with access group `sales` |
| `nobody` | `{}` | no role: 403 on role pages |

A document group only reaches the session if some source or document uses
it (`known_groups()` in `app/main.py`). So the README says: as admin, give
a source the access group `sales` first.

**No app change, and nothing in the Dockerfile or `infra/`.**

## Alternatives rejected

- **Keycloak.** It's complete, but it needs about 1 GB and a long start, and
  every test user and group has to be created up front.
- **Dex.** Its built-in password users can't carry groups, which is the
  whole point here.
- **A dev login route in the app.** It skips the real OIDC code, and the
  intent rules it out.
- **`extra_hosts: idp.localhost:host-gateway`.** It works, but it depends on
  the host firewall letting containers reach the host. The network alias
  doesn't.

## Risks

- **Port 8080 already in use** on a workstation: compose fails to start
  `idp` with a clear error. The README names the port. Changing it means
  changing the port in all three places (published port, `SERVER_PORT`,
  metadata URL).
- **A browser that doesn't resolve `*.localhost`:** current Chrome, Firefox
  and Safari all do. The README gives the `/etc/hosts` line
  (`127.0.0.1 idp.localhost`) as a fallback.
- **Anyone who can reach port 8080 can mint an admin login** for the local
  portal. The port is published on all interfaces by default, so bind it to
  `127.0.0.1:8080:8080`. Port 8000 is published the same way today, so bind
  web to `127.0.0.1` too.
- **Fake secrets in a committed file:** they are named `dev-only-…` and the
  compose file is never used in AWS (ECS task definitions come from
  `infra/`).

## Verification

Already shown with a throwaway compose project and curl, no app change:

- `admin` with `{"groups":["refs-admins"]}`: `/me` shows admin, reviewer
  and user;
- `rev` with `{"groups":["refs-reviewers"]}`: reviewer and user;
- `nobody` with `{}`: no roles, and `/admin/sources` returns 403;
- both the browser side and the web container see the issuer
  `http://idp.localhost:8080/refs`.

For the PR:

- A script with the same curl flow,
  `scripts/check_local_login.sh`, run against `docker compose up -d web`:
  the four README users get the expected `/me` roles. It's kept so the
  check can be repeated after a version bump.
- A manual browser check at http://localhost:8000 with the README table.
- `docker compose build && docker compose run --rm app pytest` (CI's
  commands) are still green.

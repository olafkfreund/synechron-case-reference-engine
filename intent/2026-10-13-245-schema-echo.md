# Intent: The local model's JSON replies are data, not the schema

## Problem

Locally, every AI step goes through `llm.complete_json()` in JSON mode
(`app/llm.py:83-87`): the JSON schema is pasted into the system prompt, and
Ollama is asked for any JSON object. `qwen3:14b` sometimes replies with the
**schema itself** (`$defs`, `properties`, `additionalProperties`) instead of
filling it in. Validation then rejects the reply, and the step fails.

- **Seen in the demo on 2026-10-13:** a research run fetched 5 pages, then
  showed "Claims could not be extracted; the sources are listed below." I
  reproduced it on the same stored pages: the reply was the schema, rejected
  in 23 s.
- **Seen in the #231 eval:** 1 of 5 research runs did the same.
- **Wider exposure:** the same call serves triage, extraction (points and
  references), the write-up, search tailoring, research queries and claims,
  and briefs (8 call sites). Any of them can hit it. Extraction and write-up
  failures are rarer only because their prompts are longer and more
  specific.

Switching local models to enforced structured output is not a safe fix on its
own. The #53 eval (`spec/2026-10-07-53-llm-local-models.md`) found that
enforced schemas collapsed small and mid-size local models to "title only".
That is why JSON mode is the local default.

## Proposed outcome

- **A schema echo is caught and recovered.** `complete_json()` recognises a
  reply that is the schema, or contains it: top-level `$defs`, `properties`,
  `type: "object"` or `additionalProperties`, and none of the model's
  required fields. It retries once, with a short corrective user turn that
  asks for the data and not the schema. A second failure raises, exactly as
  today.
- **No silent failure.** Each retry is logged by class only (alias, schema
  name, "schema echo"), never the content, so the rate can be measured.
- **The prompt cue is less echo-prone.** The schema still goes into the
  prompt, but phrased so it reads as a format to follow, followed by a short
  example of the expected shape for that model.
- **The evidence is measured, not guessed.** Before and after, a local eval
  runs the research-claims and brief calls N times each on fixed stored
  pages, counts only:
  - schema echoes
  - other validation failures
  - successes

  The eval also tries Ollama's enforced `format` (schema mode) on those two
  small, flat shapes. If enforced mode is clearly better there, a
  per-alias or per-call `mode` override is allowed. Extraction stays in JSON
  mode unless the eval shows enforced mode holds up there too.

## Affected users and systems

- **Users:** everyone using research, briefs and extraction on local models.
- **Files:** `app/llm.py` (`complete_json`), the eval script, and tests. Call
  sites change only if the eval justifies a per-call mode.
- **Bedrock:** already uses schema mode and is unchanged.

## Constraints

- **Models:** `qwen3:14b` locally, and never a `-cloud` model.
- **No content in logs.** No prompt or reply text in logs, exceptions or the
  eval output.
- **Bounded cost.** At most one retry: one extra call, and only on a failed
  reply.
- **Error handling stays the same.** Callers keep their current handling: a
  research page still lists sources when claims really fail.

## Open questions

- **Corrective retry.** Is one retry with a corrective turn enough, or should
  a second echo fall back to enforced `format` for that call? I propose one
  retry only, and to decide on the fallback from the eval numbers.

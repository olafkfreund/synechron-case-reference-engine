# Intent: A protected name written with a dot the registry doesn't have leaks into downloads

## Problem

`_loose` (`app/anonymise.py:47-53`) makes a word's trailing dot optional,
but only when the dot is in the registry name. The other direction is not
covered. A registry name without a dot doesn't match text that has one.
`apply()`, `blocked()` and `scrub()` all build their patterns with
`_pattern`, so all three miss it together. I reproduced this on main, with
the protected client "St James's Bank" and the alias "Zorp Co":

| Text | `apply()` | `blocked()` | `scrub()` |
| ---- | --------- | ----------- | --------- |
| "St. James's Bank" | unchanged | `[]` | unchanged |
| "ST. JAMES'S BANK" | unchanged | `[]` | unchanged |
| "Zorp. Co" | unchanged | `[]` | unchanged |
| "Zorp Co." (dot after the last word) | replaced | found | removed |

This leaks, it doesn't fail closed:

- A download (`render.generate`) or a search summary shows the client's real
  name.
- `research.py` sends a query containing it to the search engine. `blocked()`
  is the check at `:91`, and it misses too.

The dot is the ordinary way to write abbreviations like "St.", "Co.", "Bros."
and "Intl.". Most registries will hold one spelling.

## Proposed outcome

- A dot after a word in the text matches a registry word without the dot, as
  long as it comes before the next word or at the end. With "St James's
  Bank" registered:
  - "St. James's Bank" is replaced.
  - `blocked()` finds it if `apply()` misses it.
  - `scrub()` removes it.
- The #163 rule still holds: an inner dot is not dropped. "U.S. Bank"
  registered still doesn't match "us bank".
- `blocked(apply(text))` stays empty for these spellings.

## Affected users and systems

- `app/anonymise.py` (`_pattern` / `_loose`). Their callers are `apply`,
  `blocked`, `has_name` and `scrub`, used by `render.py`, `search.py`,
  `research.py` and `industry.py`.
- Bid team: downloads and search summaries.
- Admins no longer need to add a dotted alias for each abbreviation.

## Constraints

- Keep failing closed: `blocked()` must match at least what `apply()`
  replaces.
- Keep the #163 decision that only a trailing dot is optional.
- Use made-up names only in tests. Don't change the registry schema.

## Open questions

1. **Registry "US Bank", text "U.S. Bank":** should this match, with the dots
   inside a word? My recommendation is no. It's the mirror of #163, so add an
   alias if needed.
2. **More false matches:** a sentence break between the words, as in "…with
   Zorp. Co-founders said…", would now match "Zorp Co". That fails toward
   hiding text, which I recommend accepting.

**Decided by the user, 2026-10-12:** a dot after any word of a registered name is optional, so 'St. James's Bank' matches 'St James's Bank'. Dots inside letters are not: 'US Bank' still does not match 'U.S. Bank' (the #163 rule). A sentence break such as 'Zorp. Co-founders' being hidden is accepted.

# Intent: a Settings page for crawl configuration, connection and SSO status

## Problem

Admins can't see or safely change how the engine is connected.

- **Configuration is scattered.** It lives in Terraform variables, ECS
  environment variables, Secrets Manager and the `sources` table. Nothing
  in the portal shows which SharePoint tenant, Confluence site, models or
  SSO groups are in use.
- **Crawl targets can't be changed after creation.** The Sources page sets
  them only when a source is created, as raw JSON. Fixing a prefix, adding
  a Confluence space or narrowing file types means deleting and recreating
  the source.
- **The raw JSON is risky.** It is shown back to admins, so a secret
  typed into it would be displayed.
- **Changes aren't audited.** Source creation, enable/disable and target
  edits leave no trail. ACL and data-class changes are already audited.

## Proposed outcome

1. **Settings page, admin only.** One place showing, read-only:
   - **Connections:** SharePoint, Confluence, S3, Brave and the models, with
     their non-secret identities, whether each secret is configured (yes or
     no, never the value), and each source's last run.
   - **SSO:** the OIDC issuer, client and groups claim, which groups grant
     the user, reviewer and admin roles, and the MCP trust settings.

   Each item says where it is changed.
2. **Typed, editable crawl configuration on Sources.**
   - Per-connector fields instead of raw JSON, with unknown keys refused.
   - The source's ID is visible.
   - Scope fields (prefix, file types, spaces) can be edited. The root
     target (bucket, drive, site) is fixed once created.
   - An edit is refused while that source is crawling.
   - A scope change makes the next crawl a full one.
   - Every change is audited with old and new values.

**Decided with the requester (2026-10-14):**

- SSO and secrets are **read-only** in the portal, and still changed in
  Terraform and Secrets Manager: a bad SSO edit could lock every admin out.
- **Test-connection buttons** are a later phase, with their own SSRF
  review.

## Affected users and systems

- `app/sources.py`, `app/templates/sources.html`
- new `app/settings.py`, `app/templates/settings.html`
- `app/templates/base.html` (nav)
- `app/audit.py`, `audit.html`
- `sql/schema.sql`, `sql/roles.sql`
- admins

## Constraints

- **No secret value is ever stored in Postgres or rendered** in HTML,
  audit or errors, and neither are `*_MODEL_OPTIONS`.
- **SSO, session, database and connector secrets stay with operators.**
  The portal shows only their status.
- **Existing safeguards keep working:** ACL propagation to documents, the
  contracts toggle, the empty-listing guard against mass deletes, and the
  daily schedule in EventBridge.
- **Admin only:** `require("admin")`, and the CSRF/Origin guard applies to
  every form.

## Open questions

None. The scope was settled in plan mode on 2026-10-14.

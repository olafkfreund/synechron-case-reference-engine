# Intent: A hyphenated client name is not matched when written with a space or run together

## Problem

`anonymise._pattern` (`app/anonymise.py:33-37`) splits a name on whitespace,
then joins the words with `_JOIN` (`[\s\-‐‑–—]*`). That join is why the registered
name "Acme Bank" also matches "Acme-Bank" and "AcmeBank". The match only works
in that direction.

A name registered with a hyphen, say protected "Zorp-Tek", has no whitespace in
it. It becomes one escaped literal word, so only the exact form "Zorp-Tek" is
matched. "Zorp Tek", "ZorpTek" and "Zorp–Tek" (en dash) are:

- not replaced by `apply()`;
- not caught by `blocked()`.

So they reach generated outputs, search summaries and the text sent to the
model. This is a leak, not a fail-closed refusal.

The registry already treats these forms as the same name.
`clients._key` turns `-` into a space for the duplicate-name check, so "Zorp Tek"
cannot be registered beside "Zorp-Tek". The registry and the anonymiser
disagree.

## Proposed outcome

- A name or alias is matched in the same set of forms whichever way it was
  registered. "Zorp-Tek", "Zorp Tek", "ZorpTek" and the dash variants are
  matched both ways round.
- `apply()`, `blocked()`, `scrub()` and `has_name()` all agree, because they all
  build their patterns with `_pattern`.

## Affected users and systems

- `app/anonymise.py` (`_pattern`), and every caller through it: render, search,
  research, and the registry label check in `app/clients.py`.
- Tests: `tests/test_anonymise.py`.

## Constraints

- One change in `_pattern`, so every caller is fixed at once.
- It may only match more. It must never stop matching a form it matches today.
- The short all-caps case rule is untouched; that is #119.
- Use only made-up names; the repo is public.

## Open questions

None. The fix makes hyphens, dashes and spaces inside a registered name
interchangeable, the same as between words today.

None needed.

# Intent: Markdown output does not escape &, so an HTML entity can spell a protected name

## Problem

`render.md()` (`app/render.py:272-277`) escapes Markdown punctuation so that a
value placed into the Markdown output is inert. It doesn't escape `&`.

A case value containing an HTML character reference, for example `Zo&#114;p`,
passes `blocked()`, because the check sees the entity text and not the letter
it stands for. CommonMark viewers (GitHub, Confluence, VS Code preview) then
display it as "Zorp", a made-up protected name.

Getting there needs a literal entity in the source text, such as a
double-encoded Confluence page, so it is unlikely. But it gets past the
fail-closed check. DOCX and PPTX are not affected: docxtpl autoescapes and
python-pptx writes text literally.

## Proposed outcome

An entity in a case value appears literally in the rendered Markdown, never
as the character it encodes. So the Markdown output shows exactly the text
that `blocked()` checked.

## Affected users and systems

- Users who download Markdown: `app/render.py` (`md`).
- Tests: the render or Markdown tests.
- Not affected: DOCX, PPTX, PDF and the anonymiser.

## Constraints

- Escaping only. Values are not otherwise rewritten.
- Plain `&` in normal text ("R&D") must still read correctly once rendered.

## Open questions

None. Backslash-escaping `&` is a valid CommonMark escape: `\&` renders as
`&`, and it stops entity decoding.

None needed.

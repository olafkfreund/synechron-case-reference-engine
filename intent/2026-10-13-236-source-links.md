# Intent: Case cards link to their source documents and folders, safely

Approved in the session on 2026-10-13, after a risk review: link to the
source system, never to our stored copy, and respect client protection.

## Problem

A bid user who finds a case can't get to the project's own material: the
source documents, the folder with supporting files, images and other
deliverables. They have to search SharePoint or Confluence by hand. The
engine knows where every document came from, but it doesn't show it.

Exposing it naively would break three protections:
- **Client protection.** Folder paths and file names usually contain the
  real client name, which search deliberately replaces with an anonymised
  label for protected clients.
- **Commercial and personal data.** Engagement cases have prices, rates and
  person names stripped. The original documents still contain them.
- **Source permissions.** The portal's group mapping is set by an admin. If
  the portal served its own stored copy, or listed folders with the
  crawler's credentials, a user could reach files the source system would
  refuse them.

## Proposed outcome

- **A "Source documents" list on each case card,** on search results and
  browse:
  - the source name, and how many documents (more than one for merged
    cases)
  - each document's title, anonymised for protected clients
  - plain users see a title only when the case's client is referenceable;
    otherwise "1 document in <source>"
  - reviewers see titles as the review page does today
- **Links go to the original location only.**
  - SharePoint: the item's web address, opened in SharePoint. Confluence:
    the page link (for an attachment, its page).
  - The source system enforces the user's own permissions.
  - The engine's stored copy is never served to plain users through these
    links.
- **"Open folder"** links to the containing SharePoint folder or Confluence
  page, where the user browses supporting files and images with their own
  access. The portal doesn't list folders itself.
- **Sources with no web address,** such as uploads and file shares through
  DataSync, show "stored in the engine; ask a reviewer", with no link.
- **The crawlers record each item's web address and its folder or parent
  address.** Existing documents get them on the next crawl, without a new
  version being needed.

## Constraints

- No link, title or path to a withdrawn or deleted document, or to a
  document outside the user's groups.
- Link targets are only `https` web addresses returned by the source API,
  validated before they're stored, and shown escaped with
  `rel="noopener noreferrer"`.
- Titles and paths go through the same anonymisation and `blocked()` rules
  as everything else shown to users.
- No new credentials, and no per-user calls to the source systems.

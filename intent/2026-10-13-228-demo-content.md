# Intent: The demo shows complete case studies

Approved in the session on 2026-10-13: the user asked for the demo's sample
cases to have the content a real case study needs.

## Problem

The demo's 14 sample cases are seeded from `demo/cases.json` by
`scripts/seed_demo.py`, without calling a model. Each sample source document
is a few short paragraphs (a median of about 570 characters). Each case holds
only one-line values for challenge and solution, a few capabilities and
technologies, and one outcome.

Since #212 and #222, a real case can have:
- points per section
- written-up text per section
- technical references
- diagrams
- a completeness score

The demo shows none of this. Its previews and downloads look thin (for
example "Contoso fraud scoring"), and every demo case scores 2 of 9 for
completeness.

## Proposed outcome

- **Fuller documents.** Every demo source document is one to two pages of
  clearly fictional text: the client's situation, scope, delivery approach and
  phases, configuration and integrations, technical references, outcomes and
  lessons. The fictional names stay as they are today (Contoso, Fabrikam, and
  so on).
- **Complete seeded cases.** Each seeded case carries:
  - points per section
  - approved write-up text for Challenge, Solution, Implementation approach,
    and Configuration and integration
  - technical references and outcomes with real metric names

  Every value is quoted from its own fictional document, so the normal checks
  pass, and the cases are stamped with the current extraction version.
- **Most cases are complete.** Most demo cases reach "Complete", a few stay
  deliberately partial, and the waiting-for-review ones still show the review
  flow (including one flagged section).
- **Refreshing.** Running `scripts/demo.sh up` on an existing demo database
  brings the demo cases up to the new content. It touches only "Demo:"
  sources and never real cases or sources, such as the user's presale
  documents.
- **No model needed.** Seeding still makes no model calls.

## Constraints

- All content is fictional and plainly so. It contains no real client, person
  or deal data.
- Every quoted value must appear in its document, or seeding fails loudly.
- The demo must still work without Ollama.
